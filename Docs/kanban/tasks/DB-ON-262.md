## Контекст

Владелец 13.11.2026 попросил задавать сроки событий кодом. Даты запуска и окончания он предоставит. Публичные даты зимнего события пока не заданы.

## Готово, когда

- Есть единый кодовый реестр eventId, content/theme revision и start/end в DateTimeOffset UTC. Не назначены вымышленные праздничные даты; без корректного окна публичный новый запуск закрыт, есть Editor-only preview.
- Чистые тесты проверяют [start,end), точные границы, отсутствие/ошибку дат, start>=end, культуры/таймзоны и повторные вызовы; время подаётся через проверяемый clock provider. Источник доверенного времени/ограничения клиентских часов описаны честно.
- Один API используют выбор карты, solo, создание/присоединение к экипажу, countdown и фактический переход. Старый invite/открытый UI не обходят новый допуск.
- Предлагаемое правило приёмки: принятое до end прохождение разрешено закончить после end. Новые старты закрываются; живой return ticket и разрешённый ContinueSolo используют принятую версию контента. Если владелец выбирает другое правило, учесть при приёмке перед публичным включением, не останавливая подготовку ревью-результата.
- Event/theme revision фиксируются вместе с seed, LevelID, RunRandom/pool revision в сессии/возврате/solo-ветке. Тема не выбирается заново по сегодняшней дате; версии протокола и совместимости обновлены согласованно.
- Проверены окончание окна во время countdown, refresh, смена ведущего, потеря сети, продолжение одному и отсутствие живого экипажа. Смена темы не меняет уже принятый мир/награды.

## Результат проверки 21 ноября 2026

В `RunEventCalendar` зимнему событию назначены постоянные ID уровня, события и ревизии темы. Запись без дат закрыта для новых игроков. Одиночный старт фиксирует тему перед загрузкой, экипаж — по окончании отсчёта. Версия темы передаётся вместе с сидом, версией генератора и пула локаций. Уже принятое прохождение можно закончить после закрытия окна. Ограничения часов устройства и порядок добавления следующей темы описаны в `Docs/locations/EVENT_LEVEL_PLAN.md`.

- Правила проверены на обеих точных границах UTC, в двух культурах и четырёх часовых смещениях. Проверены пустые, ошибочные и пересекающиеся окна, обычные карты, старое зимнее сохранение и выбор ранее принятой темы.
- В Unity Play Mode отдельный клиент каталога Photon увидел открытый экипаж. Сохранённая строка каталога перестала давать допуск сразу по окончании окна. Ведущий отменил действующий отсчёт и закрыл комнату. Два игровых клиента, успевших стартовать, завершили загрузку после закрытия. После выхода ведущего другой клиент принял управление. Бывший ведущий вернулся с сохранённой версией забега. После ухода последнего играющего участника возврат стал недоступен.
- Проверены игровой экран выбора, истечение окна при ожидании отключения Photon, сохранность предыдущего одиночного прогресса и загрузка зимней сцены с готовой лодкой. Для кнопки «Продолжить одному» воспроизведена потеря связи с заранее сохранённым снимком. После очистки состояния в памяти обычный запуск восстановил зимнюю сцену и сид из одиночного сохранения.
- Воспроизводимые проверки находятся в `Assets/Online/Editor/RunEventCalendarProbe.cs` (`CheckRules`, `CheckNetwork`, `CheckGameplay`). Локальный журнал `Logs/EventCalendar262-20261121/Final.log` зафиксировал успешное завершение и восстановление пользовательских настроек редактора.

Следующий шаг ИИ — экран выбора события DB-ON-261. Владелец задаёт даты перед включением и при общей проверке WebGL принимает сценарий старта и возврата с двух устройств. Сетевой финал зимнего забега остаётся отдельной задачей DB-ON-263.
