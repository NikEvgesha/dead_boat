## Контекст

В социальном лобби сейчас трудно понять, кто рядом и кого приглашать. Имена нужны над аватарами и позднее в группе забега.

## Готово, когда

- Над удалённым аватаром показывается читаемое имя с ограничением расстояния и длины.
- Для гостя без доступного имени есть безопасное запасное название.
- Имена не содержат неподдерживаемой разметки и не перекрывают важный UI.
- Проверено на двух клиентах и при нескольких близко стоящих аватарах; отображение в забеге расширяется вместе с DB-ON-018.

## Подсказки ИИ

Начать с `Assets/Online/LobbyNetworkAvatar.cs` и DB-ON-009. Не считать имя постоянным ID игрока и не предполагать, что на всех веб-площадках доступен один профиль.

## Реализация и проверки — 15.10.2026

- `LobbyNetworkAvatar` передаёт `NetworkString<_32> DisplayName`; локальный источник проверяется раз в 2 с, сетевое значение меняется только вместе с именем. Источник — кешированное имя авторизованного издательского профиля через MirraSDK, затем кеш `PlayerAccountInfo.Nickname` Mirra Cloud. Новых запросов/входа ради имени нет. Для гостя — «Игрок N» / «Player N» по номеру участника комнаты, без вывода служебных ID.
- Общий аватар лобби/забега получает локальную world-space подпись только для удалённого игрока. Высота 2.25 м, предел 30 м, плавное исчезновение на последних 8 м; размер поддерживает читаемость на обычной дистанции и ограничивает рост вдали. Смена камеры отслеживается, позиция берётся после визуального rebasing/прикрепления водителя к лодке.
- До 24 UTF-16 символов без разрыва текстового элемента, теги/переносы/control/bidi удаляются; rich text выключен. Без raycaster/захвата ввода; при открытом курсорном меню скрыто. UI/Default учитывает глубину: имена не показываются через непрозрачные стены. Строка/ширина пересчитываются только при изменении имени/языка/участника, камера и сетевой текст проверяются 5 Гц; кадровых поисков объектов/сетевых RPC для подписи нет.
- Новый формат аватара отделён Photon AppVersion suffix `-dbnames1` в **копии** настроек игры; поиск лобби, приглашение, отправление и возврат используют один вариант. Версия приглашения/return-ticket также включает протокол: старые комнаты/коды/билеты не считаются совместимыми. App ID/CCU/глобальный asset и исходники SDK не менялись. Для общей приёмки нужны новые экипажи на одинаковой сборке.
- `AvatarNamesProbe.Validate()` PASS: безопасная строка/Unicode/длина/запасные имена RU/EN, дистанция/позади/локальный/меню, копия конфигурации. `AvatarNamesProbe.Run()` PASS на двух настоящих Photon Cloud peers в Unity 6000.3.9f1: позднее подключение с текущим именем, смена имени, запасное имя, отсутствие собственной подписи и захвата ввода, близко/далеко/позади, две подписи рядом. Render с непрозрачной стеной дал 0 белых пикселей против видимых подписей без стены; русский render просмотрен после правки размера.
- После Play `SharedRewardGameplayProbe.VerifyRestored()` PASS: owner return/identity/solo/mode keys и playModeStartScene восстановлены; компиляция чистая, редактор остановлен.
- Веб-приёмка реальных профилей, 10 близко стоящих игроков, телефон, переход Lobby ↔ Run, rebasing и водитель — позже вместе со всем пакетом. Подпись — отображаемое имя, **не доказательство личности**, аутентификация DB-ON-009 этим не закрыта. Сборка/загрузка не выполнялись.
