## Контекст

Сейчас есть прототип SerialMatching. Правило продукта: одну комнату сначала заполнить до 10, потом при нескольких комнатах распределять игроков равномерно.

2026-09-30: вход теперь сначала получает список Session в том же Photon `NetworkRunner`, выбирает открытую комнату с наименьшим числом игроков и подходящим лимитом; при отсутствии комнат использует атомарный Photon `FillRoom`. Гонка за уже занятое место повторяет подбор до двух раз. Unity импортировал скрипты без ошибок компиляции. Нужна WebGL-проверка двух клиентов и приёмка на 11+ клиентах; без этого политику заселения считать неподтверждённой.

## Готово, когда

- 11-й игрок создаёт вторую комнату.
- Существующие комнаты с местами используются повторно.
- Гонка за последнее место повторяет подбор, а не отправляет в ошибку.

## Подсказки ИИ

Сверить требуемую политику с возможностями Photon Shared; не выдавать обычный SerialMatching за точный алгоритм продукта.
