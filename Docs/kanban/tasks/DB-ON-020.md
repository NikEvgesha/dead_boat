## Контекст

- Урон применяется один раз.
- Смена Shared master не сбрасывает бой.

### Исправления и проверки

- DayHour / DayClockInitialized — снимок времени Shared master; клиент не запускает собственный цикл. Смена ведущего и возврат сохраняют время. При прямом входе ночью применяются экспозиция, туман и интенсивность солнца, даже если клиент не видел закат.
- Обычный зомби проверяет препятствия до позиции цели, не требует коллайдера удалённого FPS игрока. Удар адресуется одной выбранной цели вместо прежнего AreaAttack по всем рядом. Боссовые атаки по площади сохраняют свои правила.
- Урон отправляется RPC владельцу конкретного аватара; получатель проверяет отправителя против Shared master и меняет только локальный PlayerStatsManager. Общего HP экипажа в коде не обнаружено; прежний удар по площади мог одновременно снижать личное HP соседних игроков.
- Unity: компиляция без ошибок; геометрическая проверка PASS: удалённый персонаж без коллайдера, предел дальности, стена. Проверка прямого освещения ночью и днём PASS.
- Два реальных Cloud peers в изолированном Editor fixture: SharedRecoveryProbe PASS, включая передачу 22:30, возвращение и смену master без сброса часов. Повторный запуск с обычным автоподключением лобби мешал fixture; успешный запуск выполнен с отключённым автоматическим входом, настройки владельца восстановлены.
- Раздельное HP и попадания в реальном WebGL пока требуют ручной проверки. Оба браузера должны использовать новую сборку.

Следующий шаг — ИИ: собрать WebGL. Владелец: по очереди подставить только одного игрока под обычного зомби, проверить лечение и смерть независимо; обновить страницу ночью при оставшемся экипаже и сравнить освещение; затем выйти ведущим.

## Восстановление до первого авторитетного действия — 07.11.2026

Чужой запоздалый RPC не инвалидирует текущий State. Урон/поджог дополнительно требуют authority страницы цели.

## DB-ON-020: завершение восстановления боссов — 07.11.2026

Добавлены production BossRecoveryRules/TentacleRecoveryEvidence. Победа при потерянном callback неактивного финального дракона восстанавливается только по canonical HP<=0 и валидному MaxHP. Активная death-анимация сохраняет штатный путь. Локальный Win сам по себе больше не доказывает поражение босса: требуется canonical defeat дракона или всех частей щупальца.

Неполная группа щупалец ждёт записи: корутины остановлены, известные canonical HP не затираются sampling и локальной смертью, damage/burn к ожидающим частям запрещены. Проверка очереди выполняется с частотой sampling, после поступления записей — повторная подготовка мира и возобновление. Пустая/неполная группа, невалидные HP и локальный труп при canonicalAlive не дают ложную победу. Последний конфликт остаётся ожиданием: полноценное пересоздание такого actor этой правкой не реализовано.

Проверка поколения EnemyAuthorityEpoch отвергает действие, начатое до синхронного восстановления мира внутри Authority: восстановленное внутреннее действие разрешено, устаревший внешний callback не продолжает удар/выбор части. Покрыты melee/area/box/dive и входы щупалец. Сетевые поля и RPC не менялись; SDK/сцены/пользовательские настройки не трогали.
