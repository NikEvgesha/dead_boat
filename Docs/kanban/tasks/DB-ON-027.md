## Контекст

Оценить FPS, память, RTT, трафик и размер сборки в целевых браузерах и на площадках.

## Готово, когда

- Замеры записаны для 10 аватаров в лобби и 4 игроков в забеге.
- Определены узкие места и пороги приёмки.
- Слабое устройство остаётся играбельным по согласованному порогу.

## Подсказки ИИ

Не оптимизировать вслепую; сначала воспроизводимые замеры и профиль нагрузки.

## Источники

- `Docs/WEB_MULTIPLAYER_IMPLEMENTATION_ROADMAP.md`

## Работа 2026-10-05

По запросу владельца начаты замеры текущего кооператива. Baseline в Editor: 1000 поисков аватаров по сцене с четырьмя тестовыми аватарами и 1000 дополнительными объектами — 225.085 мс. Это локальный микрозамер, не FPS WebGL. Счётчик GC.GetAllocatedBytesForCurrentThread вернул 0, поэтому результат выделений памяти по нему не интерпретируется.

ИИ заменяет повторные scene scans реестром spawned-аватаров, кэширует компоненты и расположение записей по страницам; discovery объектов идёт 10 Гц при сохранении покадровой интерполяции. Добавлены Development/Editor-журнал показателей и probe четырёх Cloud connections с одной игровой сценой. Photon/Mirra SDK не изменяются.

Следующий шаг: ИИ — завершить замеры и regression-проверки, записать факты и ограничения. Владелец — последующая приёмка на независимых WebGL-устройствах (включая слабый телефон); Editor probe не заменяет критерии 10/4 устройств.

Последние два окна Editor: 20.6–21.6 FPS, p95 60.4–53.8 мс, три измеряемых сетевых участка вместе ~0.54–0.57 мс на кадр. Ускорение поиска не означает 160× ускорение всей игры. ## Результат стресс-этапа

Исправлен доказанный дефект: сетевой цикл каждый кадр включал физику дальних предметов вопреки KinematicCheck. Теперь активная зона учитывает весь экипаж, 10 Гц + гистерезис; вложенная физика трупа отключается у прокси и вне зоны. Контрольный предмет: sleep → wake возле удалённого участника → sleep PASS. 100 предметов + 20 настоящих трупов + принудительный маршрут 5000: PASS для создания трупов и продвижения очистки WorldRear до 4000. Не проверяет визуальное совпадение костей или перенос начала координат.

Выявлено следующее узкое место: при разделении экипажа удерживается 8580 единиц мира, 239 предметов / 136 записей врагов. Editor 6.8–7.9 FPS, items CPU 11.5–12.9 мс. После сближения 74 предмета / 70 записей врагов, последнее окно 13.4 FPS / items CPU 2.994 мс. Это неудовлетворительный стресс-результат, не выполненный критерий производительности. Подробности: `Docs/COOP_STRESS_20261005.md`.

Следующий шаг: ИИ — профилировать и сократить повторное применение состояния/регистрацию предметов и нагрузку удерживаемого мира; затем диагностический WebGL. Владелец — последующая проверка на независимых устройствах. SDK и черновик не обновлялись; статус in_progress.
