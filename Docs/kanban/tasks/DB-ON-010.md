## Контекст

Друзья обязательны: игроки должны отправлять запрос, принимать его и видеть доступность друга.

## Приёмка владельца 2026-10-08

Владелец сообщил, что загрузил сборку в тестовый черновик и вместе с другими игроками проверил: друзья работают. Это ручное подтверждение основного сценария в Яндекс WebGL, а не автоматический тест. Конкретные операции, сохранность после повторного входа, presence и идентичность между площадками этим сообщением отдельно не подтверждены. Карточка переведена в in_review; полные критерии ещё не закрыты.

Следующий шаг — ИИ: сверить реализацию сохранности аккаунта/отношений и подготовить короткий сценарий повторного входа, удаления и отказа сервиса. Владелец затем подтверждает этот сценарий на двух профилях; межплатформенную идентичность принимать отдельно.

## Готово, когда

### Дополнение 2026-10-08: запрос из чата

По запросу владельца добавлена кнопка «В друзья» для выбранного автора сообщений в LobbyChatUI. SenderId не берётся из текста/метаданных. Штатный SDK Chats использует профили, Friends использует аккаунты: RequestChatFriendAsync читает GetProfileAsync(SenderId), проверяет совпадение Id и отправляет Friends.SendAsync(AccountId). Своя выбранная персона, существующий друг и известные входящие/исходящие заявки отключают кнопку. Во время запроса кнопка занята, есть 2-секундная пауза и ограниченный кэш 50 соответствий. При смене/окончании сессии результат профиля не отправляет заявку новому аккаунту. Результат отображается в чате; закрытая панель не получает запоздалый результат.

Компиляция в Unity dead_boat и MirraChatValidation PASS (включая отсутствие HTTP от недоступной кнопки, прежние buffer/lifecycle/hide проверки). EditMode стенд использует отдельный неавторизованный социальный компонент, не создаёт постоянную игровую сессию. Реальное GetProfileAsync другого игрока → Friends.SendAsync(AccountId) и новая WebGL кнопка ещё не проверены двумя профилями. Статус in_review сохраняется. Сборка/черновик не обновлялись, SDK не менялся.

Следующий шаг — ИИ: собрать пилот с кнопкой; владелец проверяет отправку из чата, принятие в «Друзьях», невозможность добавить себя/повторить заявку и сохранность после перезахода.

- Запрос/принятие/удаление работают после повторного входа.
- Состояние друзей согласовано между площадками, где это возможно.
- Ошибки сервиса отображаются без поломки solo.

Одна сессия SDK используется также диагностической панелью; перед гостевым входом пробуем восстановление сохранённой сессии. UI открывается только в лобби, не во время выбора/ожидания отправления; SDK не изменён. Есть ограничение частоты, 20 строк на страницу и безопасное сообщение об отказе.

Проверены типы и вызовы SDK: Roslyn-компиляция изменённых файлов с Editor и WebGL define без ошибок. Play Mode/HTTP/браузер не проверены: Unity MCP сейчас не отвечает. Собственный ID пока берётся из PlayerAccountInfo.Id; правильность его адресации Friends требует двухпрофильного теста.
