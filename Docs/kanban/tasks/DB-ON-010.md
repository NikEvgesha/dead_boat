## Контекст

Друзья обязательны: игроки должны отправлять запрос, принимать его и видеть доступность друга.

## Готово, когда

- Запрос/принятие/удаление работают после повторного входа.
- Состояние друзей согласовано между площадками, где это возможно.
- Ошибки сервиса отображаются без поломки solo.

## Подсказки ИИ

Проверить Mirra Cloud API и условия доступа до интеграции; Fusion сам не хранит постоянный список друзей.

## Источники

- `Docs/WEB_MULTIPLAYER_PLAYER_FLOW.md`
- `Docs/WEB_MULTIPLAYER_IMPLEMENTATION_ROADMAP.md`


## Реализация 2026-10-06

Добавлен игровой MirraSocialService и окно LobbyFriendsUI: собственный гостевой ID, запрос по ID, входящие/исходящие заявки, принятие, отклонение, отмена и удаление. Одна сессия SDK используется также диагностической панелью; перед гостевым входом пробуем восстановление сохранённой сессии. UI открывается только в лобби, не во время выбора/ожидания отправления; SDK не изменён. Есть ограничение частоты, 20 строк на страницу и безопасное сообщение об отказе.

Проверены типы и вызовы SDK: Roslyn-компиляция изменённых файлов с Editor и WebGL define без ошибок. Play Mode/HTTP/браузер не проверены: Unity MCP сейчас не отвечает. Реальные заявки не отправлялись. Отображение presence, вход площадки, межустройственная идентичность и приглашение не реализованы. Собственный ID пока берётся из PlayerAccountInfo.Id; правильность его адресации Friends требует двухпрофильного теста.

Следующий шаг — ИИ: runtime-проверка окна и Friends на двух тестовых профилях; затем отдельная сборка для проверки владельцем. До этого карточка остаётся in_progress.
