## Контекст

После обрыва прежний участник возвращается в действующий забег, пока другие участники продолжают играть. Правила владельца от 2026-10-12 заменяют прежнее ограничение неопределённым «окном возврата»: срок определяется жизнью исходного забега, а не произвольным таймером.

## Принято владельцем 2026-10-12

- После закрытия/вылета и нового запуска предложить вернуться, если исходный забег ещё идёт и в нём остались игроки.
- Если отключились все, забег не восстанавливать и новую комнату из старого приглашения не создавать.
- При потере интернета остановить локальные игровые действия и предложить переподключение либо «Продолжить одному». Остальные участники продолжают играть.
- «Продолжить одному» отделяет локальную копию последнего подтверждённого состояния в обычный сохраняемый solo-забег. Возврат этого игрока в исходный кооп после выбора запрещён, включая перезапуск страницы.
- Постоянное сохранение хода онлайн-забега не нужно. Локальная запись для возвращения содержит идентичность/комнату/регион/версию и служит входом в живую Session, а не восстановлением опустевшего мира.

## Готово, когда

- Новый запуск предлагает возвращение только после подтверждения, что исходный забег ещё жив; без интернета его существование не утверждается.
- Возврат восстанавливает прежнего участника, личные предметы/патроны/HP/карты и актуальный общий мир без дублей. Возвращающийся появляется в безопасной точке у текущей лодки.
- Выход master не уничтожает сведения об отключившихся участниках. Неприглашённый новый игрок не занимает их место.
- Последний выход делает старую запись непригодной для возврата; попытка входа не создаёт новую комнату с прежним именем.
- Потеря сети блокирует локальные взаимодействия и открывает понятный выбор; не запускает немедленный возврат в лобби.
- Соло-ветка создаётся из последнего подтверждённого состояния и содержит только личный инвентарь игрока, а не сумки товарищей. Общая лодка/её груз и мир переходят в локальную копию; исходный кооп от этого не меняется.
- Выбор соло сохраняется до сетевого отключения/загрузки, закрывает возврат и не позволяет повторно получить ту же награду через две ветки.
- Проверены краткий обрыв, перезапуск страницы, уход всех, смена master, гонка выхода последнего участника и выбор соло.

## Подсказки ИИ

Сохранять session/run ID и стабильную идентичность; проверить уход Shared master.

Разбор кода 2026-10-12: SharedRunLifetime.ReturnAfterDisconnect сейчас сразу возвращает в лобби; SharedDepartureState.ReleaseDisconnectedItems освобождает вещи отключившегося, а Crew/BoatProfiles/Owner завязаны на PlayerRef. После отсчёта Session закрывается IsOpen=false. Реализация требует допуска прежнего участника и восстановления владения; простое повторение StartGame недостаточно. NetworkString MirraProfileId на аватаре — клиентское заявление, не серверная аутентификация. Не выдавать его за защищённую идентичность.

Следующий шаг — ИИ: протокол участника/допуска, запись для возврата, восстановление личного состояния и преобразование в solo. Владелец: после технических проверок пройти сценарии в WebGL. Полировка UI и лобби не блокирует эту задачу.

## Ошибка приёмки 2026-10-13

Владелец: два игрока начали забег, один обновил страницу; предложение возврата остаётся в подключении, все кнопки недоступны. Console-лог пока не получен. Найден потенциальный путь вечного Busy: CheckAsync при ошибке ждёт StopProbeAsync, где Shutdown был без ограничения. Это факт кода, не установленная по WebGL-логу точка зависания.

Исправляется игровой код: ограниченная остановка probe, watchdog стадий в Update по реальному времени, отмена проверки из UI, версия попытки для защиты от поздних ответов/старого finally. Билет и соло-снимок не удаляются по сетевому таймауту. SDK не меняется.

Следующий шаг — ИИ: инъекция незавершающегося Task при timeScale=0, проверка кнопок/отмены/повторной попытки, затем реальный возврат и новая тестовая сборка. Владелец: повторить обновление страницы, пока товарищ ещё играет, на двух WebGL-клиентах. Статус снова in_progress до проверок.
