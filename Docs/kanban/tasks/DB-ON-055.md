## Контекст

После StartupPauseFix второй тестировщик сообщил, что кнопки меню не работают. Скриншот и Console запрошены; неизвестно, не открывается ли меню или не работают кнопки внутри. Сохранения не удалять. В ControlManager.Update обнаружен самостоятельный риск: любой MouseButtonDown при незахваченном курсоре вызывает Locked, включая клик по UI. StandaloneInputModule при Locked не обрабатывает попадание мышью по UI.

## Готово, когда

- После потери фокуса клик по кнопке HUD/меню не захватывает курсор до обработки UI.
- Клик по игровому пространству по-прежнему восстанавливает захват и не атакует в тот же момент.
- Проверка UI не добавляет raycast или выделения памяти на каждом кадре.
- Владелец/тестировщик подтвердил исходный сценарий на WebGL.

## Подсказки ИИ

Проверить ControlManager, SettingUI, PlayerInput, EventSystem и диалоги/загрузочный Canvas. Использовать актуальную позицию мыши и EventSystem.RaycastAll при попытке восстановить захват. Защитить интерактивные элементы, не превращать декоративный полноэкранный HUD в постоянный блок захвата. Не менять SDK. Причина пользовательского случая пока не доказана; ждать уточнение/лог.

## Следующий шаг

ИИ — воспроизвести конфликт клика UI и захвата, исправить и проверить. Владелец — уточнить, какие кнопки, работают ли движение/инвентарь, прислать скриншот и Console.

## Проверки 2026-10-06

Владелец уточнил: не работают мышь и P/Tab. Конфликт мыши не объясняет весь случай, причина отказа клавиатуры пока неизвестна. Запрошены новый Console и проверка движения после клика в игровой экран.

В ControlManager добавлен raycast только при попытке захвата на MouseButtonDown; переиспользуются PointerEventData и список результатов. Верхний интерактивный UI-hit не захватывает курсор, декоративный HUD без обработчиков не мешает. SDK не менялся.

С расширением изолированного Editor-save fixture выполнен прямой boot LoadingScene → сохранённый LevelForest без входа в Lobby. PlayerInput активен, APause/AInventory имеют подписчиков; действия открывают/закрывают меню и инвентарь без исключений. Это вызов действий, не аппаратный тест клавиш. Через настоящий EventSystem проверены центры реальных MenuButton/InventoryButton: оба защищены guard; центр игрового пространства не блокирует захват. PASS. Первоначальный синтетический raycast-тест не прошёл; заменён реальными кнопками с координатами центра rect (pivot инвентаря находится на краю). Сохранения владельца изолированы, после теста Play Mode остановлен, Editor возвращён в Lobby, стартовый scale=1.

Исправление мыши локально проверено, но в черновик пока не попало. Исходный отказ P/Tab в Editor не воспроизведён. Следующий шаг: владелец/второй тестировщик — свежий Console и проверка WASD/прыжка после клика в центр; ИИ — установить причину отказа всего ввода, затем собрать общий диагностический/исправленный черновик. Не объявлять устранение исходной ошибки без браузерной приёмки.
