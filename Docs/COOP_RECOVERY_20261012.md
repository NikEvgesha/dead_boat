# Возврат в кооп и отделение соло-ветки

## Правила

Согласовано владельцем 2026-10-12: возврат возможен только в живой исходный
забег, пока там играет хотя бы один товарищ. Если вышли все, забег не
восстанавливается. Потеря сети предлагает переподключение либо явный переход
в сохраняемый одиночный забег. Онлайн-мир постоянно не сохраняем.

## Реализация

- `SharedRunRecovery` хранит в браузере запись для возврата: комнату, регион,
  каталог комнат, версию генерации/сборки и стабильный Fusion `PlayerUniqueId`.
  Запись не содержит онлайн-мир и не является серверной аутентификацией.
- При запуске с записью сначала открывается лобби. Проверка присоединяется
  по имени с `EnableClientSessionCreation=false`; отсутствующая комната никогда
  не создаётся из старой записи. `emptyRoomTtl=0` запрещает хранить пустой забег.
- Комната допускает первоначальный состав. Проверяющий клиент не создаёт
  игрового аватара: само подключение для проверки не продлевает жизнь забега.
  Уход последнего действительно играющего участника переводит состояние в
  завершённую фазу даже при подключённом проверяющем клиенте.
- Атомарный сетевой снимок личного состояния содержит инвентарь (до 32
  предметов), магазины оружия, запас патронов, здоровье, карты, опыт и монеты
  забега. Частично переданный инвентарь не заменяет предыдущий снимок.
  Владение предметами отключившегося участника сохраняется. Снимок обновляется
  при изменениях с шагом 2 секунды; это не обещание восстановления каждого кадра.
- Возврат загружает уровень с прежним сидом и актуальной дистанцией/топливом
  лодки, восстанавливает личное состояние и аватар. Генерация маршрута повторяет
  выбор старых участков без их создания; у магазинов в городах стабильные ключи.
- При обрыве локальные взаимодействия останавливаются. Соло-копия берётся из
  последнего подтверждённого состояния. Содержимое чужих сумок не копируется.
  Общая лодка, груз, предметы и HP/позиции мобов переходят в локальную копию.
- Выбор соло сначала записывает отдельное сохранение, затем удаляет запись
  возврата и отключает транспорт. Сохранение соло содержит исходный run ID;
  совпадающая запись возврата отвергается и после аварии между этими операциями.
- Соло использует обычный провайдер прогресса плюс браузерный JSON для сида,
  изменённых объектов и содержимого оружия. Обновление каждые 5 секунд и при
  паузе/выходе. Перенос этого JSON между устройствами пока не реализован.
- Сетевой каталог отправлений обновлён до v7 (chat pilot v2): старые сборки с
  другим форматом сетевого состояния не смешиваются с новой.

## Приёмка новой сборки: владелец

Оба клиента должны загрузить именно новую сборку. Старый и новый каталоги
отправлений намеренно различаются. Проверять в черновике, без публикации.

1. Создать экипаж из двух игроков и начать Forest. Первый подбирает предмет,
   меняет запас патронов/магазин, получает урон. Подождать 3–4 секунды.
2. Первый закрывает страницу. Второй продолжает путь. Первый запускает игру
   снова, получает предложение вернуться и появляется у текущей лодки.
   Проверить предмет, патроны, HP и карты; другой клиент не должен видеть дубль.
3. Повторить при выходе прежнего master: оставшийся продолжает управлять миром,
   возврат работает без потери личного состояния.
4. Отключить интернет первого. Локальные действия остановлены, второго это не
   останавливает. Вернуть сеть и нажать переподключение.
5. Повторить обрыв, выбрать и подтвердить соло. Соло продолжает играть отдельно,
   его сумка содержит свои предметы; исходная команда продолжает играть.
   После закрытия/нового запуска соло сохраняется, предложения возврата нет.
6. Проверить в соло выброс/подбор, сжигание топлива, продажу и смерть моба;
   перезапуск не должен возвращать уже потраченный предмет. Отдельно пройти
   бой после восстановления мобов и бой с боссом.
7. Закрыть всех участников коопа. Повторный вход не создаёт старую комнату.
   Проверить гонку: пока первый видит предложение возврата, второй выходит.
8. Отложить предложение кнопкой «Позже» и открыть его снова отдельной кнопкой
   в лобби. Затем начать новый одиночный забег: старый сид соло-ветки не должен
   подменить новое сохранение при следующем запуске.

Постоянные награды пока не принимать: они остаются DB-ON-021. При отказе
передать полный Console-лог и номер сборки, указав шаг этого списка.

## Стабильное хранение билета WebGL — 2026-10-13

Владелец подтвердил настоящий сценарий: обычный браузер создал экипаж на двоих, IAB присоединился и поплыл; после перезапуска IAB оказался в начале solo. Это ошибка приёмки, а не одиночный тест.

Билет и Fusion identity ранее сохранялись только в PlayerPrefs. Unity документирует URL-зависимый persistentDataPath WebGL: [Application.persistentDataPath](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/application/persistentdatapath); [PlayerPrefs](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/playerprefs) использует IndexedDB. Каталог iframe IAB действительно менялся при запуске черновика. Потеря именно этого билета в IndexedDB не прочитана и окончательная причина конкретного отказа не установлена.

Добавлен собственный SharedReturnStorage / .jslib: только небольшие билет/идентичность читаются и синхронно записываются в localStorage игрового origin. Это устраняет зависимость этих двух записей от каталога сборки и от асинхронного сброса PlayerPrefs. Сохраняется fallback PlayerPrefs и миграция старого значения при отсутствии браузерной записи. Удаление оставляет пустой маркер, чтобы старый URL не воскресил билет. Смена origin/очистка данных браузера по-прежнему уничтожает доступ к локальному билету; это не облачная сохранённая копия онлайн-мира. SDK, обычные сохранения, большой solo-снимок не менялись.

Диагностика показывает только наличие записи, backend и успешность записи, без комнаты/идентичности/данных игрока. При недоступном browser storage сообщается warning и используется PlayerPrefs.
