# Mirra Cloud: журнал интеграции и обратной связи

Это отдельный журнал для бета-теста Mirra Cloud на Dead Boat. Он помогает отличать **увиденное в нашем проекте**, **заявленное в документации** и **гипотезы, которые ещё нужно проверить**. Игровые требования и статус разработки остаются в `Docs/kanban/tasks/`; здесь собираем опыт использования сервиса и предложения его команде. Ничего из этого файла не отправлено Mirra автоматически.

## Как пополнять

- Для нового наблюдения указывать дату, SDK/Unity/браузер, шаги воспроизведения, фактический и ожидаемый результат. При повторной проверке дополнять запись, а не стирать прежний результат.
- Статусы: **проверено** — воспроизведено в указанной среде; **по документации** — прочитано в официальном источнике, но не проверено в игре; **гипотеза** — вопрос или предположение; **исправлено** — повторный тест подтвердил изменение.
- Для предложения команде Mirra записывать конкретный сценарий и пользу. Не выдавать особенности ранней версии за подтверждённый дефект.
- Не добавлять API-токены, сервисные ключи, секреты площадок, данные игроков и полные тексты приватных ответов API. Локальная конфигурация SDK исключена из Git.

## Среда и достигнутое на 2026-09-29

| Компонент | Состояние |
| --- | --- |
| Mirra Hub | Отдельный проект `Dead Boat`, ветка `main`; проект `BlockKick` оставлен тестовым. |
| Платформа | `Yandex Games`, ключ `yandex-games`, тип Web, гостевой вход включён. |
| Unity | Dead Boat на Unity `6000.3.9f1`; `com.mirrahub.cloud-sdk` закреплён на `v0.10.0`. Пакет импортирован, пакет и отдельная тестовая сцена скомпилировались в batchmode без ошибок C#. |
| Фактический WebGL-вход | Не проверен: для тестовой сборки нужен клиентский API-токен и конфигурация. Подтверждение на создание токена запрошено у владельца. |
| Социальные функции | Друзья, чат и фильтр пока не проверены на двух клиентах. |

SDK установлен по [официальной инструкции и README](https://github.com/Mirra-Hub/Unity-Cloud-Sdk#readme). Пробная сцена и способ сборки описаны в [`Assets/Online/README.md`](../Assets/Online/README.md). Этот SDK отличается от `MirraSDK 5`, который уже обслуживает площадки и рекламу.

Это проверка импорта, а не обещание полной совместимости или работоспособности WebGL. | Простой воспроизводимый старт, версия закреплена в `packages-lock.json`. |

## Трение, вопросы и предложения Mirra

| ID | Статус и сценарий | Влияние на нас | Предложение или вопрос |
| --- | --- | --- | --- |
| MC-05 | **Проверено в узком окне Hub, 2026-09-29.** При телефонной ширине появлялось сообщение о неподдерживаемой мобильной версии; владелец тоже отметил, что консоль доступна только при компьютерном разрешении. | Быстро посмотреть проект или токены на узком экране нельзя. | Сделать хотя бы адаптивное чтение списка проектов, платформ, ошибок и квот; формы редактирования можно развивать отдельно. Повторить тест на реальном телефоне. |
| MC-06 | **Проверено в Hub, 2026-09-29.** В форме создания клиентского API-токена видно только поле названия; срок действия, набор прав и привязка к платформе/ветке в этой форме не представлены. Мы не проверяли, существуют ли ограничения в другой части продукта. | Неясно, как ограничить последствия раскрытия токена, который войдёт в публичный WebGL-билд. | Показать модель прав клиентского токена, возможность ограничить сервисы/платформу и срок; отдельно объяснить, чем он отличается от секретного ключа сервисного аккаунта. |
| MC-07 | **Проверено в Hub, 2026-09-29.** Для интеграции «Яндекс Игры» запрашиваются ID приложения и секретный ключ. Пока интеграция не добавлена, соответствующий способ входа недоступен в форме платформы. Гостевой вход включён отдельно, но ещё не испытан в билде. | Нужно безопасно связать гостя с подтверждённым аккаунтом площадки, чтобы друзья и прогресс пережили смену браузера. | Дать отдельный пример для Unity WebGL в iframe Яндекс Игр: получение данных площадки, вход, переход гостя к аккаунту и обработка отказа. Секрет должен оставаться только на стороне Mirra. |
| MC-08 | **По документации SDK; поведение сервера не проверено.** `ProfanityFilter.CheckAsync` — отдельный вызов клиента перед отправкой текста; `Chats.SendMessageAsync` и `EditMessageAsync` — отдельные методы. [Фильтр](https://github.com/Mirra-Hub/Unity-Cloud-Sdk/blob/main/docs/services/ProfanityFilter.md) и [чат](https://github.com/Mirra-Hub/Unity-Cloud-Sdk/blob/main/docs/services/Chats.md) описаны раздельно. | Клиентскую предварительную проверку можно обойти изменённым клиентом. Для публичного чата нужна гарантия на сервере. | Уточнить, применяет ли сервер чата фильтр при прямой отправке **и редактировании**; если да, документировать настройку, отказ и лимиты. Если нет, дать серверный hook/политику, чтобы запрещённый текст не доставлялся. |
| MC-09 | **Гипотеза до замера WebGL.** Пакет поставляет несколько сервисов и встроенные зависимости; вклад в размер и время загрузки Dead Boat пока неизвестен. | На веб-площадках размер и память критичны. | После нашего замера предложить Mirra таблицу вклада пакета в WebGL-сборку и способ подключать только используемые функции, если вклад окажется существенным. |
| MC-10 | **По README SDK.** Публичный API ещё в серии `0.x` и может меняться между минорными версиями. | Обновления могут потребовать правок интеграции. | Поддерживать краткую таблицу миграции с последней стабильной версии, отмечать breaking changes и рекомендованные версии Unity. |

## План проверок, после которых обновить журнал

1. На отдельной тестовой сцене выполнить гостевой вход в Unity Editor и WebGL, затем в iframe черновика Яндекс Игр. Записать HTTP-результат и условия браузера без токена и данных игрока.
2. Сравнить распакованный и сжатый размер WebGL до и после SDK, память и время загрузки на одинаковых настройках. Лишь после измерения оценивать MC-09.
3. Проверить друзей на двух независимых браузерных профилях: запрос, принятие, удаление, повторный вход и доступность.
4. Проверить канал чата, порядок сообщений, reconnect, лимиты, ошибки и стоимость запросов. Для MC-08 отдельно испытать прямую отправку и редактирование без клиентского `CheckAsync`; тестировать только в закрытом проекте и без реальной брани в публичном чате.
5. Проверить процедуру связывания гостя с Яндекс Играми и возможности подтверждения той же личности для Photon, не передавая секреты в билд.
6. По итогам нескольких проверок собрать короткое письмо или issue для Mirra: воспроизведение, версия, фактический результат, ожидаемый результат и предложение. Отправлять только после согласования с владельцем.
