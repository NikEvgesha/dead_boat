# Mirra Cloud: журнал интеграции и обратной связи

Это отдельный журнал для бета-теста Mirra Cloud на Dead Boat. Он помогает отличать **увиденное в нашем проекте**, **заявленное в документации** и **гипотезы, которые ещё нужно проверить**. Игровые требования и статус разработки остаются в `Docs/kanban/tasks/`; здесь собираем опыт использования сервиса и предложения его команде. Ничего из этого файла не отправлено Mirra автоматически.

## Как пополнять

- Для нового наблюдения указывать дату, SDK/Unity/браузер, шаги воспроизведения, фактический и ожидаемый результат. При повторной проверке дополнять запись, а не стирать прежний результат.
- Статусы: **проверено** — воспроизведено в указанной среде; **по документации** — прочитано в официальном источнике, но не проверено в игре; **гипотеза** — вопрос или предположение; **исправлено** — повторный тест подтвердил изменение.
- Для предложения команде Mirra записывать конкретный сценарий и пользу. Не выдавать особенности ранней версии за подтверждённый дефект.
- Не добавлять API-токены, сервисные ключи, секреты площадок, данные игроков и полные тексты приватных ответов API. Локальная конфигурация SDK исключена из Git.

## Объявление об обновлении и повторная проверка 2026-09-29

Владелец передал анонс SDK `0.10.0` и изменений облачной платформы. Наш `Packages/manifest.json` уже закреплён на теге `v0.10.0` (коммит `25ed14a2`); обновлять зависимость по этому анонсу не требуется. В установленном [changelog SDK](https://github.com/Mirra-Hub/Unity-Cloud-Sdk/blob/v0.10.0/Packages/com.mirrahub.cloud-sdk/CHANGELOG.md) и коде проверены селектор платформ с предупреждением о несовпадении типа Web/PC/Mobile, получение ассетов по пути, `Chats.GetMyChannelsAsync` и удаление Remote Config. Предупреждение о типе платформы — проверка конфигурации в Editor, а не подтверждение работы сети в WebGL.

Исправления CORS, лидербордов, пагинации и страниц Hub заявлены в переданном анонсе; их поведение в Dead Boat не проверено. После анонса повторно открыт существующий черновик Яндекс Игр со сборкой без токена: гостевой вход по-прежнему показал `HTTP 500 Unknown Error`. Сборка, CSP и список разрешённых хостов не менялись; поэтому этот повторный тест не изолирует причину. Для следующей проверки сохраняется план DB-ON-050: полноценная игровая сборка, запрос `sdk.mirracloud.com` в CSP и новый тест в iframe.

Полноценная игровая WebGL-сборка с отдельной диагностикой Mirra создана в Unity 6000.3.9f1 и упакована для тестового черновика. Проверка состоялась только на уровне успешной сборки, состава ZIP и размеров файлов; запуск в браузере и загрузка в Яндекс Игры ещё не состоялись. В проекте SDK остался неизменённым.

Повторная проверка 2026-09-30 в консоли Яндекс Игр под аккаунтом владельца: сохранённый черновик `424778` показывает архив 19,19 МБ от 29.09.2026 20:34:40 и всё ещё запускает отдельную сцену `Mirra Cloud - Yandex Games connection test`, где гостевой вход сообщает `HTTP 500 Unknown Error`. Владелец сообщил о загрузке новой сборки, но в этом черновике она пока не подтверждена; возможно, загрузка не была сохранена или относится к другому черновику — это **гипотезы**. В действующем списке CSP `sdk.mirracloud.com` отсутствует, форма запроса доступна для редактирования. SDK и сервис Mirra этой проверкой не менялись. Предложение команде Mirra по наблюдаемому `500` остаётся MC-12; после сохранения игрового архива и изменения CSP нужен повторный тест.

Это проверка импорта, а не обещание полной совместимости или работоспособности WebGL. | Простой воспроизводимый старт, версия закреплена в `packages-lock.json`. |

## Трение, вопросы и предложения Mirra

| ID | Статус и сценарий | Влияние на нас | Предложение или вопрос |
| --- | --- | --- | --- |
| MC-05 | **Проверено в узком окне Hub, 2026-09-29.** При телефонной ширине появлялось сообщение о неподдерживаемой мобильной версии; владелец тоже отметил, что консоль доступна только при компьютерном разрешении. | Быстро посмотреть проект или токены на узком экране нельзя. | Сделать хотя бы адаптивное чтение списка проектов, платформ, ошибок и квот; формы редактирования можно развивать отдельно. Повторить тест на реальном телефоне. |
| MC-06 | **Проверено в Hub и коде SDK v0.10.0, 2026-09-29.** В форме создания API-токена видно только поле названия; срок действия, набор прав и привязка к платформе/ветке там не представлены. Поле `Configuration.Token` читается инструментами Editor, но не используется гостевым входом рантайма. | При хранении заполненного `Configuration.asset` в Resources токен всё равно попадает в публичный WebGL-архив без пользы для игрока. Сборка Dead Boat теперь останавливается при непустом поле. **По сообщению владельца от 2026-09-29**, ранее использованный тестовый токен удалён; удаление в Hub отдельно не проверялось. | Разделить Editor API-токен и публичную клиентскую конфигурацию в примере Unity WebGL; явно предупредить о содержимом Resources и описать права/срок/отзыв токена. |
| MC-07 | **Проверено в Hub и локальном WebGL, 2026-09-29.** Для интеграции «Яндекс Игры» запрашиваются ID приложения и секретный ключ. Пока интеграция не добавлена, вход площадки недоступен; гостевой вход в локальном браузере успешен. | Нужно безопасно связать гостя с подтверждённым аккаунтом площадки, чтобы друзья и прогресс пережили смену браузера. | Дать отдельный пример для Unity WebGL в iframe Яндекс Игр: получение данных площадки, вход, переход гостя к аккаунту и обработка отказа. Секрет должен оставаться только на стороне Mirra. |
| MC-08 | **По документации SDK; поведение сервера не проверено.** `ProfanityFilter.CheckAsync` — отдельный вызов клиента перед отправкой текста; `Chats.SendMessageAsync` и `EditMessageAsync` — отдельные методы. [Фильтр](https://github.com/Mirra-Hub/Unity-Cloud-Sdk/blob/main/docs/services/ProfanityFilter.md) и [чат](https://github.com/Mirra-Hub/Unity-Cloud-Sdk/blob/main/docs/services/Chats.md) описаны раздельно. | Клиентскую предварительную проверку можно обойти изменённым клиентом. Для публичного чата нужна гарантия на сервере. | Уточнить, применяет ли сервер чата фильтр при прямой отправке **и редактировании**; если да, документировать настройку, отказ и лимиты. Если нет, дать серверный hook/политику, чтобы запрещённый текст не доставлялся. |
| MC-09 | **Гипотеза до замера WebGL.** Пакет поставляет несколько сервисов и встроенные зависимости; вклад в размер и время загрузки Dead Boat пока неизвестен. | На веб-площадках размер и память критичны. | После нашего замера предложить Mirra таблицу вклада пакета в WebGL-сборку и способ подключать только используемые функции, если вклад окажется существенным. |
| MC-10 | **По README SDK.** Публичный API ещё в серии `0.x` и может меняться между минорными версиями. | Обновления могут потребовать правок интеграции. | Поддерживать краткую таблицу миграции с последней стабильной версии, отмечать breaking changes и рекомендованные версии Unity. |
| MC-11 | **Проверено, Unity 6000.3.9f1 / SDK v0.10.0 / WebGL, 2026-09-29.** В отдельной сцене вызов `MirraCloudSDK.Initialize()` останавливал главный цикл с `unityWebView is not defined`: SDK инициализирует UnityWebView даже перед одним `LoginGuestAsync`, а обычный шаблон игры не подключает jQuery и `unity-webview.js`. После добавления локальных файлов из совместимого шаблона SDK WebGL стартует и гостевой вход на localhost успешен. | Пользователь SDK получает чёрный экран до первого запроса и может принять его за проблему сети. | Внести WebGL WebView JS в пакетный postprocess или сделать WebView ленивым для функций, которым он нужен; в инструкции явно указать обязательные зависимости обычного шаблона. |
| MC-12 | **Проверено в браузере, 2026-09-29.** Локальная WebGL-сборка показывает `Guest login OK`, прямой тест endpoint с `PlatformKey: yandex-games` отвечает `200`; в iframe черновика Яндекс Игр тот же Unity вызов показывает `HTTP 500 Unknown Error`. Ошибка повторилась в новом архиве с пустым `Configuration.Token`. В списке разрешённых хостов черновика есть Photon, но нет `sdk.mirracloud.com`. Запрос CSP не отправлен: консоль Яндекса требует перед ним полноценный игровой черновик, а текущий архив — изолированная тестовая сцена. Сам CSP пока не доказан единственной причиной ошибки. | Встроенную проверку на целевой площадке нельзя признать успешной, хотя локальное соединение работает. | Документировать для Яндекс Игр необходимые хосты/директивы CSP и диагностику случаев, когда браузер блокирует запрос, а SDK показывает общий `HTTP 500 Unknown Error`. Повторить тест после разрешения хоста. |
| MC-13 | **Проверено на localhost, 2026-09-29.** На фоне успешного гостевого входа лог содержит `Analytics request failed: common.not_found — event 'SessionsStarted' not found.` | Сообщение выглядит как ошибка SDK, хотя авторизация уже сработала; непонятно, нужно ли создать событие вручную в Empty-проекте. | Добавить `SessionsStarted` в начальный шаблон проекта или объяснить в SDK, когда оно должно существовать и как отключить автоматическую отправку. |

## План проверок, после которых обновить журнал

1. После возврата полноценного игрового черновика запросить в CSP Яндекс Игр `sdk.mirracloud.com`, дождаться применения и повторить гостевой вход в iframe. Не принимать текущий `500` за доказанный отказ сервера: локальный WebGL и прямой запрос успешны. В Unity Editor тест ещё не выполнен.
2. Сравнить распакованный и сжатый размер WebGL до и после SDK, память и время загрузки на одинаковых настройках. Лишь после измерения оценивать MC-09.
3. Проверить друзей на двух независимых браузерных профилях: запрос, принятие, удаление, повторный вход и доступность.
4. Проверить канал чата, порядок сообщений, reconnect, лимиты, ошибки и стоимость запросов. Для MC-08 отдельно испытать прямую отправку и редактирование без клиентского `CheckAsync`; тестировать только в закрытом проекте и без реальной брани в публичном чате.
5. Проверить процедуру связывания гостя с Яндекс Играми и возможности подтверждения той же личности для Photon, не передавая секреты в билд.
6. По итогам нескольких проверок собрать короткое письмо или issue для Mirra: воспроизведение, версия, фактический результат, ожидаемый результат и предложение. Отправлять только после согласования с владельцем.
