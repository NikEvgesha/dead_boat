# Mirra Cloud: журнал интеграции и обратной связи

Это отдельный журнал для бета-теста Mirra Cloud на Dead Boat. Он помогает отличать **увиденное в нашем проекте**, **заявленное в документации** и **гипотезы, которые ещё нужно проверить**. Игровые требования и статус разработки остаются в `Docs/kanban/tasks/`; здесь собираем опыт использования сервиса и предложения его команде. Ничего из этого файла не отправлено Mirra автоматически.

## Как пополнять

- Для нового наблюдения указывать дату, SDK/Unity/браузер, шаги воспроизведения, фактический и ожидаемый результат. При повторной проверке дополнять запись, а не стирать прежний результат.
- Статусы: **проверено** — воспроизведено в указанной среде; **по документации** — прочитано в официальном источнике, но не проверено в игре; **гипотеза** — вопрос или предположение; **исправлено** — повторный тест подтвердил изменение.
- Для предложения команде Mirra записывать конкретный сценарий и пользу. Не выдавать особенности ранней версии за подтверждённый дефект.
- Не добавлять API-токены, сервисные ключи, секреты площадок, данные игроков и полные тексты приватных ответов API. Локальная конфигурация SDK исключена из Git.

## Объявление об обновлении и повторная проверка 2026-09-29

Владелец передал анонс SDK `0.10.0` и изменений облачной платформы. Наш `Packages/manifest.json` уже закреплён на теге `v0.10.0` (коммит `25ed14a2`); обновлять зависимость по этому анонсу не требуется. В установленном [changelog SDK](https://github.com/Mirra-Hub/Unity-Cloud-Sdk/blob/v0.10.0/Packages/com.mirrahub.cloud-sdk/CHANGELOG.md) и коде проверены селектор платформ с предупреждением о несовпадении типа Web/PC/Mobile, получение ассетов по пути, `Chats.GetMyChannelsAsync` и удаление Remote Config. Предупреждение о типе платформы — проверка конфигурации в Editor, а не подтверждение работы сети в WebGL.

Исправления CORS, лидербордов, пагинации и страниц Hub заявлены в переданном анонсе; их поведение в Dead Boat не проверено. После анонса повторно открыт существующий черновик Яндекс Игр со сборкой без токена: гостевой вход по-прежнему показал `HTTP 500 Unknown Error`. Сборка, CSP и список разрешённых хостов не менялись; поэтому этот повторный тест не изолирует причину. Для следующей проверки сохраняется план DB-ON-050: полноценная игровая сборка, запрос `sdk.mirracloud.com` в CSP и новый тест в iframe.

Полноценная игровая WebGL-сборка с отдельной диагностикой Mirra создана в Unity 6000.3.9f1 и упакована для тестового черновика. Проверка состоялась только на уровне успешной сборки, состава ZIP и размеров файлов; запуск в браузере и загрузка в Яндекс Игры ещё не состоялись. В проекте SDK остался неизменённым.

Повторная проверка 2026-09-30 в консоли Яндекс Игр под аккаунтом владельца: сохранённый черновик `424778` показывает архив 19,19 МБ от 29.09.2026 20:34:40 и всё ещё запускает отдельную сцену `Mirra Cloud - Yandex Games connection test`, где гостевой вход сообщает `HTTP 500 Unknown Error`. Владелец сообщил о загрузке новой сборки, но в этом черновике она пока не подтверждена; возможно, загрузка не была сохранена или относится к другому черновику — это **гипотезы**. В действующем списке CSP `sdk.mirracloud.com` отсутствует, форма запроса доступна для редактирования. SDK и сервис Mirra этой проверкой не менялись. Предложение команде Mirra по наблюдаемому `500` остаётся MC-12; после сохранения игрового архива и изменения CSP нужен повторный тест.

Позднее 2026-09-30 владелец повторно загрузил сборку: консоль `424778` показала новый архив 32,08 Mb и отметку 13:04:08, игровое лобби запустилось с диагностической панелью. В iframe гостевой вход по-прежнему показывал `HTTP 500 Unknown Error` до изменения CSP. Запрос на **единственный** хост `sdk.mirracloud.com` принят консолью Яндекса и находится на рассмотрении; одобрение и повторный вход пока **не проверены**. Это не доказывает, что CSP — единственная причина `500`. Консоль показывает замечание о распакованном файле больше 100 МБ, хотя для подготовленного ZIP локальный замер самого крупного распакованного WASM давал 76,56 МиБ; надо уточнить, относится ли замечание к новой сборке и как Яндекс считает размер. Предложение Mirra по диагностике ошибки остаётся MC-12.

Уточнение по размеру: ZIP текущей игровой сборки после распаковки содержит всего 33 635 173 байта, а крупнейший файл в нём — 19 694 173 байта. Официальный пункт 1.21 Яндекс Игр ограничивает именно суммарное содержимое архива до ZIP-сжатия 100 МБ. Размер 76,56 МиБ относится к **дополнительной внутренней Brotli-распаковке** Unity WASM и не равен размеру файла в ZIP. Замечание консоли, вероятно, осталось от прежней development-сборки, как уже наблюдалось 2026-09-28; его происхождение для текущей загрузки отдельно не подтверждено.

Проверка после сообщения владельца о готовности CSP, 2026-09-30: в консоли Яндекс Игр черновика `424778` хост `sdk.mirracloud.com` **проверен в действующем списке**, рядом с ранее разрешёнными хостами. В обычном URL черновика (`draft=true`) после обновления страницы и в новой вкладке та же игровая сборка продолжает показывать `Login failed: HTTP 500 Unknown Error`. При двух загрузках URL с официальной debug-панелью Яндекс Игр (`debug-mode=16&draft=true`) в том же браузере диагностическая панель игры показала `Guest login OK`. Это **смешанный результат**, не доказательство стабильной работы обычного черновика и не доказательство, что debug-панель меняет CSP. Различие между URL, состояние гостевого ID, сетевую ошибку и ответ API нужно проверить отдельно. Игра при отказе остаётся доступной в лобби; два независимых профиля ещё не проверены. SDK и Mirra Hub в этой проверке не менялись.

Дополнительная проверка: после закрытия прочих игровых вкладок единственная обычная вкладка была перезагружена и снова показала `HTTP 500 Unknown Error`. Одновременное открытие нескольких вкладок не требуется для воспроизведения этой ошибки.

Повторная проверка 2026-09-30, Unity `6000.3.9f1`, SDK `v0.10.0`, обычная ссылка черновика Яндекс Игр `424778`: после успешной сборки пяти игровых сцен загружен диагностический ZIP `DeadBoatMirraPlayableDraft-20260930-diagnostics.zip` (33 220 419 байт, файл Яндекса `13615682`). `Configuration.Token` перед сборкой пуст; SDK не изменён. После сохранения консоль показала статус прежнего черновика «Отклонен»; новый тестовый черновик создан с тем же архивом, без модерации и публикации. В новой обычной вкладке полноценная игра дошла до лобби, а панель показала `Guest login OK`. Это **проверено в одной браузерной сессии** и улучшает предыдущий результат с `500`; стабильность после повторных входов и два независимых профиля ещё не проверены. Поля ошибок `Type` и `NetworkResult` при успешном входе не появляются. Предложение MC-12 остаётся актуальным для диагностики возможных повторных отказов.

Новый факт из игрового черновика 2026-09-30: владелец показал диалог Unity с `ReferenceError: unityInstance is not defined` из `unity-webview.js:44:17`, хотя гостевой вход завершился успешно. Проверка шаблона сборки установила, что `unityApp.js` держал экземпляр Unity только в локальном `then((unityInstance) => ...)`, а WebView ожидает глобальный `unityInstance`. Исправлен **игровой шаблон**, который публикует экземпляр глобально и буферизует ранние сообщения WebView; SDK оставлен без изменений. Компиляция Unity успешна, повторная WebGL-проверка ошибки ещё не сделана. **Предложение Mirra:** дать в инструкции Unity WebGL точный контракт для `unityInstance` и пример безопасной инициализации, в том числе для iframe-событий до завершения загрузки Unity.

Повторный тест 2026-09-30: новая игровая WebGL-сборка с исправленным шаблоном загружена в тестовый черновик Яндекс Игр `424778` (архив 33 212 602 байта, файл Яндекса `13617427`). В одной обычной загрузке iframe дошёл до лобби и `Guest login OK`, первоначальная ошибка `unityInstance is not defined` при старте не показалась. Это **проверено для одного запуска**, не гарантия для всех браузеров. Позднейшая автоматизированная попытка кликнуть Unity Canvas вызвала отдельную `WrongDocumentError` для pointer lock в инструменте управления браузером; не считать её повторением ошибки WebView. SDK не меняли. Предложение Mirra о документировании глобального экземпляра Unity остаётся актуальным.
