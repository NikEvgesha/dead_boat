# Серверные ограничения чата Dead Boat

Дата: 2026-10-07. Рабочий список вопросов для команды Mirra; не отправлен.

## Подтверждено

Шаблон `deadboat-lobby-v1` связан с `deadboat-chat`. Сервер маскирует проверенные ru/en примеры при Send и Edit, включая историю. Игра дополнительно проверяет текст перед отправкой, ограничивает его 200 символами и выдерживает 2 секунды между отправками. Эти клиентские ограничения можно обойти.

В установленном SDK 0.10.0 есть события OnMemberBanned/OnChannelDeleted, но не найдены публичные методы жалобы, mute или установки лимита частоты. На просмотренных формах шаблона и канала таких настроек нет. Это наблюдение о доступном интерфейсе, не утверждение об отсутствии серверных лимитов.

## Что необходимо выяснить

1. Есть ли обязательный серверный лимит Send/Edit по профилю, а также по каналу? Какие значения по умолчанию, какой код ошибки, как долго ждать после отказа? Для Dead Boat желателен лимит порядка одного нового сообщения за 2 секунды, с небольшим разрешённым всплеском и отдельной защитой от частых правок.
2. Ограничивается ли длина Body на сервере до фильтрации? Можно ли задать 200 символов для нашего шаблона?
3. Как отправлять жалобу от игрока, кто получает её и как ограничить спам самими жалобами? Можно ли получить безопасный идентификатор сообщения, не копируя персональные данные в логи игры?
4. Как применяются временный mute и ban: к профилю/каналу/проекту? Переживает ли ограничение переподключение? Какие события и ошибки получает SDK?
5. Как очищать пустые каналы и членство после закрытия вкладки без Leave? Есть ли TTL, retention и ограничение числа каналов, создаваемых профилем?
6. Если потребуется Cloud Code, можно ли запретить прямой клиентский Send/Edit и доставлять сообщения только через доверенный серверный путь? Одного дополнительного вызова Cloud Code перед обычным Send недостаточно: изменённый клиент пропустит этот вызов.

## Решение до ответа

Игровой чат остаётся выключенным. В отдельном диагностическом канале разрешены ограниченные технические проверки; нагрузочный спам не запускается. Локальное скрытие сообщений пользователя может быть полезно для UI, но не заменяет серверный mute.

Ответственные: ИИ готовит проверяемую интеграцию и фиксирует результаты; владелец при необходимости передаёт вопросы Mirra; команда Mirra подтверждает серверные гарантии. Обратная связь без запроса владельца не отправляется.
