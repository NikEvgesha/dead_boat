# Учебный первый ран v2 — сценарная карта

## Актуальные требования владельца

Уточнение после прототипа v1: использовать существующее начальное обучение как основу; активный забег не более10мин; насыщенное сценарное вступление со всеми основными игровыми системами, животными и разными карточками; по маршруту ровно2здания и короткий участок до мини-босса. Босс — дракон первой локации, меньшего размера и со значительно меньшим HP для одиночного прохождения. Предложена ручная карта вместо процедурных спавнов.

Прежний автономный greybox ниже — технический эксперимент, не основа окончательного контроллера/инвентаря/боя и не согласованный маршрут v2. Его текущая сцена ещё НЕ реализует новые требования. Автовход новичков и восстановление теперь подключены; актуальный результат описан в разделе «Однократный вход и контрольные точки» ниже.


## Однократный вход и контрольные точки — 07.11.2026

DB-ON-047: LoadingManager после готовности SDK проверяет отдельный профиль `DeadBoat.FirstRun.Profile.v2`. Отсутствующая запись у нового профиля означает Running; начальная сцена — FirstRunAuthored без рекламы перехода и без Photon. Обучающая сцена включена в EditorBuildSettings, но не добавлена в каталог выбора уровней. Для старого профиля без новой записи сохраняется прежний маршрут (Legacy): учитываются сохранённый забег, старое обучение, метапрогресс и ожидающий сетевой возврат.

Состояния Running / Completed / Skipped / Legacy независимы от старого tutorial-флага. Явный выход через GameManager или LoadingManager закрывает обучение как Skipped; победа — Completed. Оба состояния сохраняются перед переходом и запрещают повторный вход, включая попытку прямого LoadLocation. Перезапуск незавершённого урока оставляет Running. Смена версии контента сбрасывает только незавершённый checkpoint, не открывает закрытый урок. Для неизвестной схемы профиль не перезаписывается; повреждённый checkpoint безопасно начинает урок заново.

Данные идут через публичный MirraSDK.Data текущего профиля; SDK не изменялся. Вне SDK используется PlayerPrefs. Непрофильное браузерное значение не переносится поверх данных другого платформенного аккаунта. FirstRunSave отделяет деньги/HP/опыт/карты/инвентарь учебного рана от обычного слота, а настройки и постоянные покупки остаются у основного провайдера.

Checkpoint обновляется раз в 2 секунды и при потере фокуса/паузе/выходе приложения. Сохраняются этап сценария и старого обучения, лодка/топливо, игрок/HP/деньги/опыт, карточные бонусы, оружие/магазин/резерв патронов, сумка, свободные и закреплённые предметы, проданные/сожжённые/собранные предметы, невзятый мешок денег, текущая покупка, HP охранников и дракона, флаги яйца/выстрела/спутника. Продажа помечает предмет использованным до Destroy, выплата мешка помечается до события: сохранение в тот же кадр не дублирует выплату. Полученное яйцо имеет прежний одноразовый receipt; повторное восстановление его не размножает.

Это периодический checkpoint, а не запись каждого кадра: при аварийном закрытии возможен откат последних секунд; завершение записи платформой при принудительном закрытии вкладки ещё требует WebGL-проверки. Скорости Rigidbody и позы костей ragdoll не сериализуются; труп восстанавливается переносимым статичным предметом. Предмет, удерживаемый вне сумки, возвращается свободно в сохранённую точку, а не со старой ссылкой на руку. При невозможности восстановить шаблон предмета запускается свежий урок с предупреждением, без вечной загрузки.

## Сценарные события, карточки и мини-дракон — следующий этап v2

`FirstRunAuthoredRoute` теперь ведёт последовательность по фактам действий: старые семь шагов → первый дом/охранник → яйцо → первый выбор → второй дом/оружие/патроны/выстрел → второй охранник → второй выбор → 900 м/мини-дракон → отдельный учебный финал → Lobby. На отметках 300 и 600 м действует runtime-ограничитель лодки: геометрическое перемещение и счётчик пути останавливаются вместе, топливо во время ожидания не расходуется. Выбор карточки снимает соответствующее ограничение. Обычные/сетевые забеги получают бесконечный лимит по умолчанию. Случайные QuestManager/QuestTrigger в новой сцене отключены. Штатные семь TutorialStep сохранены; их текущему индексу добавлены отдельные текстовые подсказки вместо конфликтующих заданий обычного рана. Карточки открываются штатным LevelUpUi и LevelUpButtomUI с действующими локализацией и FEEL. Учебные предложения бесплатны, не тратят обычные level-up credits, не повышают редкость за рекламу, не позволяют платный/рекламный переброс; соответствующие кнопки скрываются на время предложения и восстанавливаются после него. Уведомление о яйце скрывается и приостанавливает свой таймер, пока открыта карточная панель. Выход из сцены во время выбора отменяет его callback и возвращает интерфейс в обычное состояние. Первый набор: «Ритм боя», «Кровавый договор», расширение сумки; второй: «Верная рука», «Новый заход», «Последний довод». Берётся первая существующая редкость каждого ресурса; для вместимости это +1 слот. XP по-прежнему накапливается, но обычные случайные предложения не смешиваются с двумя заданными. Повторный callback завершённого предложения не может выдать вторую карточку.

Яйцо курицы собирается настоящим Inventory/EggCollectibleItem и получает однократный receipt `deadboat-first-run-egg-v2`. Его использование в гнезде остаётся механикой лобби. После находки появляется **временная** курица-спутник: следует за игроком, слегка парит, не участвует в физике лодки; бонусы стадии1 берутся из существующего каталога (+3% движения/+8% XP в текущих данных) и проходят через EggAnimalBuffService. Питомец не добавляется в постоянную коллекцию и снимает временные бонусы при выходе. Это демонстрация спутника, а не мгновенное вылупление найденного яйца.

Утерянные обязательные яйцо/оружие/патроны восстанавливаются по сохранённым точкам. Свободный предмет, упавший ниже Y=-15, возвращается на точку; уничтоженный обязательный предмет создаётся из исходного префаба. При повторном создании яйца сохраняется однократный receipt. Если у дракона полностью исчерпаны магазин и резерв пистолета, появляется одна запасная коробка патронов на лодке. Это страховки прототипа; не вводить их в обычные уровни автоматически.

## Целевой маршрут и бюджет времени

Ручная компактная карта: стартовый причал → здание1 → здание2 → небольшая арена дракона. У причала торговые точки без дополнительного обязательного здания. Только эти2здания являются обязательными остановками; обычные случайные города, волны и задания на этом маршруте выключаются. Ключевые предметы/враги/карточки/спутник назначаются сценарием, фиксированный seed и версия остаются для декора/воспроизводимости, не вместо сценария.

| Участок | Целевое активное время | Действия и новое впечатление |
|---|---|---|
| Стартовый причал |0–2мин| Перенести существующую цепочку TutorialStep: подобрать ценность, продать, забрать деньги, купить необходимое, подобрать/перенести/заправить топливо, сесть за руль. Сохранять существующие PC/touch подсказки и стрелку; перепривязать ссылки к ручной карте. Не добавлять новый контроллер вместо штатного. |
| Здание1 |2–3.5мин| Короткая вылазка: меч, слабая угроза, полезная добыча, гарантированное яйцо. Первый выбор карточки, эффект быстро проявляется. Предлагается учебный спутник на время этого рана, который реально следует за игроком/даёт бонус. Найденное яйцо остаётся предметом для будущего лобби. |
| Переход и здание2 |3.5–5.5мин| Спутник заметен во время плавания. Во втором здании показать огнестрельное оружие, патроны/перезарядку, перенос или крепление полезного груза; небольшая заранее заданная группа врагов. Второй выбор карточки дополняет первый. |
| Подход к арене |5.5–6.5мин| Короткая визуальная подготовка: дракон виден заранее, есть боезапас/лечение перед боем. Можно дать третий короткий выбор карточки, если время ручного теста позволяет. Никакого пустого длинного плавания. |
| Мини-дракон и финал |6.5–8мин| Уменьшенный вариант существующего дракона, понятные атаки и заметный урон от обычного доступного оружия. Одиночная победа, краткое поздравление, вход в лобби с объяснением яйца/животных. |

План8мин оставляет2мин запаса на чтение и ошибки. Это бюджет проектирования, не измеренное время новичка; потолок10мин требует ручных прогонов. Не вводить поражение только из-за времени. Меньше UI-пауз, одна текущая цель, гарантированный боезапас, отсутствие обязательных рекламных/платных действий и ожидания инкубатора. Концентрация достигается расположением и быстрым применением новой возможности, а не количеством одновременно открытых окон.

## Что показать действием

Основной цикл: поднять/положить/сумка → ценность/продажа/денежная сумка → покупка → топливо/лодка → меч → огнестрел/патроны/перезарядка → животное → карточки/синергия → босс → лобби/яйцо. На пару точек можно свести несколько связанных действий. Профессии и долгий мета-прогресс показывать коротким финальным приглашением в лобби, их полный каталог в десятиминутный ран не помещать. Точный набор остаётся дизайном до сборки маршрута.

Карточки:2обязательных предложения и опциональное3е, каждый раз выбор из небольшого заранее составленного набора. Использовать существующие карточки/RU/EN/FEEL. Первый эффект должен ощущаться сразу; второй показать другое направление или дополнить выбор. Не выдавать случайно неработающий для доступного оружия эффект. Полный каталог карточек не обязателен для первого знакомства.

Животные: временный учебный спутник — рекомендация, ещё не утверждённая постоянная награда. Не включать настоящее многоминутное вылупление посреди рана: нынешнее правило использования яйца в лобби сохраняется. Постоянный подарок/награду за яйцо согласовать отдельно при балансировке; сейчас ничего не начислено.

# Первый опыт новичка — прототип v1

## Цель и выбор

Дать первую понятную победу и объяснить основной цикл: добыча → сумка → топливо → лодка → угроза → прибытие. Принятые ранее правила: новичок играет офлайн, сценарий повторяемый, закрытие вкладки допускает продолжение, явный выход в лобби закрывает обучение для профиля.

Варианты: (1) оставить старые подсказки в обычном случайном забеге — дешевле, но тяжело контролировать сложность/темп; (2) отдельный небольшой маршрут — контролируемые объекты и паузы, нужна отдельная интеграция сохранений; (3) полноценная постановочная глава — больше выразительности, но высокие затраты на контент и риск затянуть вступление. Рекомендация для проверки: вариант2, сначала greybox. Целевая длительность3–5мин — гипотеза, а не измеренный результат.

Мобильное управление и перенос строк ещё не приняты. В полноценной версии следует использовать штатные управление, инвентарь, оружие и лодку вместо дублирования механик.

## Что реализовано

Assets/Scenes/FirstRunPrototype.unity, запуск Tools → Dead Boat → First Run → Play Prototype. Сцена отсутствует в обычном Build Settings и каталоге уровней. Геометрия создаётся при Play. Seed14052026, ContentVersion1, отдельный поток first-run-decor-v1; канистра/двигатель/руль/угроза/финиш имеют фиксированные позиции и не зависят от декоративного рандома. Обычный глобальный Random не меняется.

FirstRunProgress — отдельная последовательная модель. CheckpointKey DeadBoat.FirstRun.Prototype.v1 сохраняет шаг, дистанцию, HP и удары по угрозе. Запись не чаще2Гц, при смене этапа сразу; Save на паузе/выходе. Неверный JSON/версия/диапазоны запускают прототип сначала. Completed/Skipped терминальны: обычный запуск прототипа не начинает их заново. Для обновления страницы это локальная модель восстановления, а не гарантированное облачное сохранение. В Editor smoke ключ прототипа и настройки владельца резервируются и восстанавливаются при Stop.

Малый hook LoadingManager обслуживает только явный выход из запущенного прототипа (одноразовый статический флаг); остальные запуски остаются прежними. Автоматической отправки новых пользователей в эту сцену ПОКА НЕТ. Веб-сборка не создавалась.

## Проверка и границы

Editor Validate проверяет модель, seed-stream, ordered gates, контрольную точку, retry и терминальные состояния. Play Smoke проверяет реальную сцену, близость подбора/engine/wheel, действия сумки и модель пути/угрозы/финиша без Photon/SaveManager. Это автоматическое прохождение через методы; оно не подтверждает ощущения ручного управления или длительность. Визуально проверен Game View. Первый снимок выявил унаследованный timeScale0; standalone scene теперь запускает свой clock1, Editor восстанавливает прежний clock после Stop.

Критерии ручного опыта: игрок понимает ближайшую цель без объяснений, замечает канистру, не застревает у сумки/руля, получает понятную первую победу. Если нужен частый внешний комментарий — сначала упростить шаги и ориентиры. Никаких фактических результатов на новичках пока нет.
