# DB-ON-264: размер экземпляра предмета

Работа выбрана после [сверки канбана](ACTIVE_WORK_QUEUE_20261114.md). Причина: production fitting уменьшает предмет под поверхность, а отдельные пути восстановления создавали полный каталожный экземпляр. Это влияло на модель и коллайдер, а не только на иконку.

## Контракт

`SharedItemRecord`, `SharedRecoveryItem` и `SoloWorldItem` получили `Vector3 WorldScale`. Это мировые длины локальных осей экземпляра, включая знак отражения, а не localScale относительно меняющегося родителя. Каноническое значение фиксирует ведущий после размещения. Claim, перенос, ammo update, освобождение и takeover сохраняют его; обычный RPC_ItemState не позволяет незаметно перезаписать размер.

Новый личный предмет передаёт размер при первой регистрации. Восстановление сумки использует актуальный canonical record вместо устаревшего личного снимка. Последующий capture тоже предпочитает canonical размер; масштаб руки не становится новым размером предмета.

`SharedItemScale.Apply` задаёт абсолютный размер после окончательного parent/rotation, избегая записи неизменившегося значения. Он использует текущий составной lossyScale, а не только scale родителя. Повторный вызов не должен повторять коэффициент fitting. Нулевой/нечисловой/бесконечный размер не применяется.

Под произвольно повёрнутым неравномерно масштабированным родителем может возникать shear. Сохраняются длины осей и отсутствие накопления; полное устранение такого искажения одним localScale не обещается. Не задавать подобные якоря ради деформации физического груза. Сравнение native AABB в тесте делается при одинаковой ориентации, а не между разными поворотами.

## Подключённые пути

| Путь | Применение размера |
|---|---|
| Регистрация созданной добычи | После production fitting, вместе с template/pose/ammo. |
| Холодное обнаружение dropped/cargo | Общая фабрика SharedItemScale.CreateReplica. |
| Independent suspend/restore | Та же фабрика из live record. |
| Региональный restore | Canonical размер поверх вновь подогнанного candidate; без повторного умножения. |
| Сумка восстановления | Canonical record выигрывает; размер применяется до/после вставки в инвентарь. |
| Переключение предмета в руке | Сохранить размер до перепривязки, применить после окончательного localRotation. |
| Прокси/смена ведущего | Применение после окончательного pose, в том числе при неизменившейся позиции. |
| Прикрепление к лодке | После SetParent и BoatLocalPosition/Rotation. |
| ContinueSolo и его последующее сохранение | WorldScale проходит через world records, Bag и JSON, применяется при восстановлении. |
| Удалённый equipped visual | Отдельный multiplier относительно исходного каталожного размера; авторские pose/entry.scale сохранены. |

WorldRegionArchive уже копировал записи целиком; сравнение dormancy теперь учитывает и WorldScale. Изменившийся live размер не считается совпадающим со старой спящей записью.

## Совместимость и стоимость

Новый сетевой суффикс заканчивается на **`-itemscale1`**. Его используют подключения лобби, экипажа и восстановления, а также версия приглашения/return ticket. Старые и новые layout сетевых структур не должны встречаться в одной комнате. Обновление префабов/SDK ради этого не выполнялось.

RunRandom.Version остаётся **6**, ключ `DeadBoat.SoloBranch.v1` сохранён. Старый JSON без поля получает zero/unknown: сохраняем generated fit, если candidate уже создан, либо каталожный размер холодной реплики. Точный исторический fitted размер, который не записывался, восстановить невозможно. Чужие/старые сохранения не очищались. Обычный исторический offline provider хранит имена предметов; эта работа не объявляет мигрированными все его форматы.

Fusion weaving измерил SharedItemRecord **96 байт** и SharedRecoveryItem **32 байта**: по **12 байт** нового состояния на запись относительно расчётных старых схем. Это ёмкость состояния, а не трафик в байтах/сек. WorldScale не пересылается отдельным покадровым RPC.

Полные prefab NetworkObject.GetWordCount: WorldPage **20 344 байта**, DepartureState **10 600**, Avatar **1004**; все ниже 32 KiB. Эти значения не включают полную историю snapshots и внешний allocator и не являются замером Web heap.

## Проверки

Native EditMode в Unity 6000.3.9f1 прошёл **859 утверждений** и **75 повторных применений**:

- настоящий Loot203_T10_Coffer: rootScale 2 / width 1,016 м → production fit rootScale 1,41732287 / width 0,72000003 м;
- обе production cold factories и обычный raw clone после Apply дают те же Renderer и BoxCollider bounds;
- inventory/hand/boat, rotated nonuniform anchors и detach не накапливают масштаб;
- JSON world/bag, legacy missing field, zero/NaN/Infinity, presentation multiplier и новый protocol settings copy;
- фактический Fusion word count структур, behaviours и целых NetworkObject.

Отдельный SharedRunValidation проверил независимость RNG, реконструкцию и **5 настоящих пулов × 200 локаций**. Это не изменение последовательности генератора.

**Два настоящих Cloud-подключения — PASS:** production RegisterItem передал fitted размер; claim → inventory → drop сохранили его и поля патронов; atomic recovery bag получил WorldScale. Реальный SharedItemsRuntime создал холодную dropped-реплику размером 0,72 м, а WorldIndependentStreaming удалил/восстановил её с теми же Renderer/Collider bounds. Пять повторных reconciliation не изменили размер. После отключения первого ведущего второй получил authority состояния и страниц с прежними размерами, ammo и bag fields.

Это одна пустая игровая среда с двумя transport peers. Physics была на паузе; distant-focus флаг задан стендом явно. Не проверены полный recovery coordinator/UI, настоящий бой/перезарядка, инвентарный UI, загрузка игровой сцены, реальные Physics steps и независимые WebGL-клиенты. JSON roundtrip не выдаётся за полный перезапуск приложения.

Batch-процесс завершился **exit 0**. После cleanup нет активного shared/solo контекста и Runner. Шесть файлов конфигурации совпали с состоянием до теста; 29 прежних локальных файлов также совпали побайтно. Автоматическое изменение ready defines MCP во время подготовки Editor возвращено к сохранённой локальной версии; SDK/пакеты в коммит не входят. Перезаписанный Editor перевод строк у source mesh возвращён; содержимое меша не менялось.

Зафиксированная выжимка доказательств с полными native значениями и хешами: [ITEM_INSTANCE_SCALE_20261114.json](ITEM_INSTANCE_SCALE_20261114.json). Сырые отчёты и журнал остаются локально в `Logs/ItemScale264-20261114/`.

## Повтор проверки

Только в отдельном экземпляре Editor при закрытом другом Unity этого проекта:

```powershell
& 'E:\Unity\Editors\6000.3.9f1\Editor\Unity.exe' -batchmode -nographics -projectPath 'E:\GitFork\dead_boat' -executeMethod DeadBoat.Online.Editor.SharedItemScaleBatch.Run -logFile 'E:\GitFork\dead_boat\Logs\ItemScale264-20261114\Unity.log'
```

Без `-quit`: host сам завершает процесс после очистки. Он ждёт окончания стартового импорта/перекомпиляции, запускает native probe и два изолированных Cloud-подключения в пустой Play-сцене. Не запускаются SaveManager, игровая сцена, реклама и UI восстановления. Player Build не создаётся. Перед повтором сохранить локальные настройки и после выхода сверить их: установленный MCP resolver может сам синхронизировать ready defines. Возвращать только изменения теста, сохраняя собственную исходную версию, а не весь ProjectSettings из HEAD.
