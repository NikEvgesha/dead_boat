# Documentation Workflow Template (for other projects)

Этот шаблон можно переносить в любой проект, где нужна дисциплина по TODO/Docs/Journal.

## 1) Минимальный набор файлов

В корень проекта:
- `START_PROMPT.md`
- `GPT_JOURNAL.md`

В рабочую папку механики:
- `TODO.md` или `TODO_List.md` (единый backlog)

В `Docs/`:
- `*_SYSTEM_SPEC.md` (что делает фича и как устроена),
- `*_SYSTEM_SETUP.md` (как настроить в Unity/редакторе),
- при необходимости `*_TEST_PLAN.md`.

## 2) Правила ведения

- Любое заметное изменение фиксируется в TODO.
- После заметного шага добавляется запись в `GPT_JOURNAL.md`.
- Если изменены архитектура, настройки или контракты, обновляется соответствующий `Docs/*`.
- TODO не смешивается с длинными историческими логами; для истории используется Journal.

## 3) Формат TODO (рекомендуемый)

TODO должен содержать:
- снимок состояния (дата),
- таблицы по фичам (`Фича`, `Статус`, `Готовность`, `Комментарий`),
- секцию приоритетов (`P0/P1/P2`),
- ручной чеклист для Unity/QA,
- регресс-чеклист перед релизом.

## 4) Формат Journal (рекомендуемый)

Для каждой заметной записи:
- дата,
- что изменено,
- почему это важно,
- что осталось.

Записи должны быть короткими и техническими, без лишней воды.

## 5) Шаги миграции в новый проект

1. Скопировать этот набор файлов в новый репозиторий.
2. Переименовать `*_SYSTEM_SPEC.md` и `*_SYSTEM_SETUP.md` под нужную механику.
3. В `START_PROMPT.md` обновить список "обязательных файлов".
4. Создать первую запись в `GPT_JOURNAL.md` с текущим снимком состояния.
5. Перевести локальный TODO в формат таблиц и приоритетов.

## 6) Признак, что процесс работает

- Новому участнику хватает 5-10 минут, чтобы понять текущий статус.
- На старте сессии не нужно заново "раскапывать" проект.
- Любая незавершенная задача имеет понятный статус и следующий шаг.
