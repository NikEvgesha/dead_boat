# Бонусы лодки: проверка DB-ON-024

Правило осталось прежним: карты лодки складываются, профессия и совокупный набор животных одного игрока выбираются по лучшему значению **каждого** параметра. Внутри одного игрока животные сохраняют `AnimalRunBuffs.Add`: плоские величины складываются, множители перемножаются. Личные HP, урон и вместимость не попадают в общий профиль лодки.

`SharedBoatBonusMath.Calculate` выделен из authority-обновления. Проценты карточек складываются как отклонения от 1; для расхода выбирается меньший множитель, для пополнения — больший. Максимум профессии для топлива/скорости сравнивается после применения её плоского бонуса и множителя к базе с карточками — прежняя согласованная формула. Животный плоский бонус добавляется затем. У отрицательных сумм расхода/пополнения нижняя граница0, нового ограничения баланса не вводили. Пустой вход даёт нейтральные конечные значения вместо Infinity/NaN. Числовые промежуточные суммы карточек считают в double.

Authority использует один переиспользуемый буфер на4 профиля, заполняемый в порядке зафиксированного экипажа. Новый ведущий заполняет свой буфер из существующих сетевых BoatProfiles; локальный кеш не является источником бонусов. Повторный RPC по-прежнему заменяет запись по PlayerRef, а не добавляет вторую.

## Найденные проблемы состава

- Раньше расчёт обходил все BoatProfiles, включая подтверждённо отказавшихся (AbandonedMask). Теперь отбор через Includes, тот же критерий членства, что у остальных сетевых действий. Записи истории не удаляются, но их бонусы не участвуют. Заполнение проверяется для допущенных слотов, а не равенством числа записей первоначальному CrewCount: отказавшийся до первого профиля не блокирует старт лодки.
- Временный обрыв не удаляет участника из зафиксированного экипажа и сохраняет его последний подтверждённый профиль, чтобы скачок ёмкости не происходил из-за refresh/смены ведущего. После возврата новый профиль заменяет старый. Подтверждённый окончательный отказ уменьшает общий набор; топливо ограничивается новой ёмкостью прежним правилом.
- Обычный `LeaveAsync(preserveReturn:false)` раньше стирал только локальный билет и завершал транспорт. Теперь перед shutdown при живом незавершённом забеге отправляется RPC_AbandonRun с ожиданием отражённого отказа до1.5с. Ошибка/таймаут журналируются и не запрещают выход. При preserveReturn=true, отсутствии связи, загрузке или общей победе этот путь не применяется. Серверное подтверждение при недоступной сети не обещается: без доставленного отказа профиль остаётся как для временно отсутствующего участника. Никаких новых таймаутов удаления offline-игроков не вводили.

Для выходящего ведущего перед shutdown оставлено0.2с в пределах того же бюджета1.5с на публикацию изменённого snapshot: собственная локальная отметка ещё не доказывает доставку следующему ведущему. Это best-effort, не новый надёжный серверный протокол подтверждения; реальный выход ведущего требует пакетного сетевого теста. Сетевые поля, размер профиля, комнаты, SDK и постоянные награды не менялись.

## Проверки

`SharedBoatBonusProbe.Run` в Unity6000.3.9f1: исторический двухпрофильный пример2360/155/2.184; четыре профиля с разными лучшими параметрами2600/229/расход0.336/пополнение3.36; все24 перестановки дают побитово одинаковый итог. Проверены новый локальный буфер, сокращённый набор, замена карточного вклада, игнорирование старого хвоста буфера, нейтральный вход и реальные базовые параметры BoardController.prefab, сложение животных внутри игрока, нулевая граница и отклонение NaN/Infinity профиля. После прогрева10000вызовов калькулятора выделили0managed bytes в данном Editor-потоке. Это измерение калькулятора, не всей игры и не WebGL.

Это чистый Editor-тест формулы и компиляция интеграции, **не** новый прогон4Photon peers, фактическая доставка выхода, отключение/возврат или handoff. Прежний исторический двухpeer-тест не выдаётся за новую проверку этих сценариев. Сборки/черновика нет.

Далее **владелец** в общем пакете: четыре разных набора, карточка топлива/скорости во время забега, refresh с сохранением параметров, возврат, смена ведущего, обычный выход в лобби и продолжение одному. Сверить общие значения, отсутствие удвоения после возврата, новый максимум/остаток топлива при окончательном отказе; при разрыве сети учесть отсутствие доставки отказа. DB-ON-024 остаётся in_review.
