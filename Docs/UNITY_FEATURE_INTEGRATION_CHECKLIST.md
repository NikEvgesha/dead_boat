# Пошаговая настройка и проверка фич в Unity

Обновлено: 2026-05-06

Документ нужен как рабочая инструкция: что именно открыть в Unity, какие объекты поставить, какие ссылки прокинуть в Inspector и как проверить, что все работает.

## 0. Подготовка

1. Открой проект в Unity `6000.3.9f1`.
2. Открой сцену `Assets/Scenes/LoadingScene.unity`.
3. Открой окно `AI Game Developer`.
4. Проверь:
   - `Status: RUNNING`;
   - MCP configured для Codex;
   - URL `http://localhost:22348`;
   - в Console нет ошибок.
5. Подожди, пока Unity закончит компиляцию.
6. Открой Console и очисти старые сообщения.

Ожидаемый результат:

- Unity не компилирует.
- Console пустая.
- Play Mode запускается без ошибок.

## 1. Общий быстрый regression

Делай после любой крупной настройки сцены.

1. Запусти Play Mode из `LoadingScene`.
2. Дождись загрузки игры/лобби.
3. Начни обычный забег.
4. Подбери обычный предмет.
5. Продай предмет.
6. Купи/используй топливо.
7. Получи опыт.
8. Выбери карточку уровня.
9. Заверши забег.
10. Вернись в лобби.
11. Начни новый забег.

Проверить:

- обычный инвентарь работает;
- продажа работает;
- топливо работает;
- карточки уровня работают;
- после конца забега обычный инвентарь сбрасывается;
- после конца забега карточные бонусы сбрасываются;
- в Console нет ошибок.

## 2. Настройка фичи яиц

### 2.1. Проверить каталог яиц

1. Открой asset:
   - `Assets/Resources/Eggs/EggHatchingCatalog.asset`
2. Проверь, что есть яйца:
   - `egg_chicken`;
   - `egg_condor`.
3. Проверь, что есть животные:
   - `chicken`;
   - `condor`.
4. Для каждого яйца проверь:
   - `eggId`;
   - `title`;
   - `incubationSeconds`;
   - `skipCostGems`;
   - `eggPreviewPrefab`;
   - `hatchResults`.
5. Для каждого животного проверь:
   - `animalId`;
   - `title`;
   - `maxStage`;
   - список стадий;
   - prefab стадии;
   - tint;
   - buffs.

Если чего-то нет:

- добавь записи руками в Inspector;
- пока можно использовать текущие временные prefab-ы;
- финальные модели/иконки можно заменить позже.

### 2.2. Проверить спавн яиц в забеге

1. Найди location spawn collection, где лежат обычные предметы локаций.
2. Проверь, что prefab-ы яиц добавлены в spawn pool.
3. Открой prefab яйца.
4. Проверь, что на prefab есть компонент `EggCollectibleItem`.
5. Проверь, что в `EggCollectibleItem` указан правильный `eggId`.

Нужно:

- яйцо должно спавниться как объект на локации;
- при подборе оно не должно попадать в обычный инвентарь;
- оно должно попадать в отдельное egg storage.

### 2.3. Поставить менеджер яиц в лобби

В лобби-сцене:

1. Создай пустой объект:
   - `EggHatchingManager`
2. Добавь компонент:
   - `EggHatchingManager`
3. В Inspector проверь/назначь:
   - `Catalog` или оставь пустым, чтобы он грузился из `Resources/Eggs/EggHatchingCatalog`;
   - ссылки на UI панели, если они есть в сцене;
   - включенный режим временного UI, если финального UI пока нет.

Если объект уже есть:

- не создавай второй;
- проверь ссылки и параметры на существующем.

### 2.4. Поставить гнезда в лобби

Для каждого гнезда:

1. Создай объект в лобби, например:
   - `EggNest_01`
2. Поставь его в удобное место.
3. Добавь collider trigger-зону взаимодействия.
4. Добавь компонент:
   - `EggNestPoint`
5. В Inspector укажи:
   - уникальный `nestId`, например `nest_01`;
   - точку/anchor для preview яйца или животного;
   - canvas/hint, если есть;
   - ссылку на `EggNestSelectionPanel`, если поле есть.

Рекомендация:

- сделай минимум 1 гнездо для первого теста;
- потом добавь 2-3 гнезда, когда базовый loop работает.

### 2.5. Поставить точки размещения животных на корабле

На корабле в лобби:

1. Создай объект-точку, например:
   - `AnimalPlacement_01`
2. Поставь его на корабль.
3. Сделай его дочерним объектом корабля, если животное должно двигаться вместе с кораблем.
4. Добавь trigger collider.
5. Добавь компонент:
   - `AnimalPlacementPoint`
6. В Inspector укажи:
   - уникальный `pointId`, например `boat_pet_01`;
   - anchor/transform, куда будет ставиться животное;
   - ссылку на `AnimalPlacementSelectionPanel`, если нужна.

Рекомендация:

- сначала сделай 1 точку;
- после smoke добавь остальные точки.

### 2.6. Поставить merge station

В лобби:

1. Создай объект:
   - `AnimalMergeStation`
2. Поставь его в отдельное понятное место.
3. Добавь trigger collider.
4. Добавь компонент:
   - `AnimalMergePoint`
5. В Inspector укажи:
   - ссылку на `AnimalMergeSelectionPanel`, если есть;
   - hint canvas, если есть.

Если финального UI нет:

- временный UI должен помочь проверить механику.

### 2.7. UI для яиц

Нужны панели:

- `EggNestSelectionPanel` - выбор яйца для гнезда;
- `AnimalPlacementSelectionPanel` - выбор животного для точки на корабле;
- `AnimalMergeSelectionPanel` - выбор животного для мерджа;
- `EggStorageDisplay` - счетчик яиц, если хочешь видеть яйца в UI забега/лобби;
- `EggNestUI` - отображение таймера/ready state, если используется.

Минимально для теста:

1. Проверь, что временный UI создается.
2. Если временный UI неудобен, создай Canvas и панели руками.
3. Прокинь ссылки в:
   - `EggHatchingManager`;
   - `EggNestPoint`;
   - `AnimalPlacementPoint`;
   - `AnimalMergePoint`.

### 2.8. Smoke test яиц

1. Запусти Play Mode.
2. Начни забег.
3. Найди и подбери яйцо.
4. Проверь, что яйцо не попало в обычный инвентарь.
5. Заверши забег.
6. Вернись в лобби.
7. Подойди к гнезду.
8. Открой UI гнезда.
9. Выбери яйцо.
10. Запусти инкубацию.
11. Дождись таймера или скипни за gems.
12. Проверь, что в гнезде появился зверь.
13. Подойди и забери зверя.
14. Подойди к точке на корабле.
15. Выбери зверя и поставь его.
16. Начни следующий забег.
17. Проверь, что баф животного влияет на статы.
18. Вернись в лобби.
19. Получи 2 одинаковых зверя одной стадии.
20. Подойди к merge station.
21. Смерджи их.

Ожидаемый результат:

- яйцо хранится отдельно;
- гнездо сохраняет таймер;
- готовый зверь ждет ручного сбора;
- зверь попадает в animal inventory;
- зверь ставится на корабль;
- баф применяется в забеге;
- merge съедает 2 одинаковых зверя и дает 1 следующей стадии;
- Console без ошибок.

## 3. Настройка фичи профессий

### 3.1. Проверить каталог профессий

1. Открой asset:
   - `Assets/Resources/Professions/ProfessionCatalog.asset`
2. Проверь профессии:
   - `yunga`;
   - `mechanic`;
   - `hunter`;
   - `trader`.
3. Для каждой профессии проверь:
   - `professionId`;
   - `title`;
   - `description`;
   - `icon`;
   - `starterItems`;
   - `startCoinsBonus`;
   - `startGemsBonus`;
   - `passiveBonuses`;
   - `availableInRandomUnlockPool`;
   - `randomUnlockWeight`;
   - `directSoftCurrencyCost`;
   - `directSoftCurrencyType`;
   - `purchaseProductId`;
   - `allowSoftCurrencyFallbackWhenPurchasesUnavailable`.

Что нужно заполнить руками:

- реальные названия профессий;
- описания;
- иконки;
- стартовые предметы;
- реальные цены;
- реальные `purchaseProductId` для площадок с платежами.

Важно:

- новая игра должна начинаться без выбранной профессии;
- `defaultUnlocked` может открывать профессию, но не должен автоматически выбирать ее;
- если покупок на площадке нет, direct buy должен работать через soft currency fallback.

### 3.2. Поставить точку выбора профессии в лобби

В лобби-сцене:

1. Создай объект:
   - `ProfessionPoint`
2. Поставь его там, где игрок должен выбирать профессию.
3. Добавь trigger collider.
4. Добавь компонент:
   - `ProfessionNpcPoint`
5. В Inspector укажи:
   - `Info Canvas` или hint объект;
   - `Selection Panel`;
   - `Touch Open Button`, если нужен mobile/touch;
   - `Close Panel On Trigger Exit`, если хочешь закрывать UI при выходе из зоны.

### 3.3. Настроить ProfessionSelectionPanel

На Canvas:

1. Создай объект панели:
   - `ProfessionSelectionPanel`
2. Добавь компонент:
   - `ProfessionSelectionPanel`
3. В Inspector укажи:
   - `Catalog`: `Assets/Resources/Professions/ProfessionCatalog.asset`
   - `Panel`: root панели;
   - title text;
   - description text;
   - starter items text;
   - perks text;
   - status text;
   - message text;
   - unlock price text;
   - profession icon;
   - lock object;
   - apply button;
   - next button;
   - prev button;
   - unlock random button;
   - direct buy button;
   - close button.

Если финальной панели нет:

- можно оставить временный UI;
- компонент сам создаст простую временную панель, если включен temporary UI.

### 3.4. Настроить цены профессий

В `ProfessionSelectionPanel`:

- `Unlock Random Price Coins`: стартовая цена random unlock;
- `Unlock Random Currency Type`: обычно `Coins`;
- `Scale Unlock Price By Opened Count`: включить, если цена должна расти;
- `Unlock Price Step Coins`: шаг роста цены;
- `Unlock Price Max Coins`: максимум цены.

В каждой профессии в каталоге:

- `directSoftCurrencyCost`: цена прямой покупки на площадках без real payments;
- `directSoftCurrencyType`: обычно `Coins`;
- `purchaseProductId`: id покупки для площадок с real payments;
- `allowSoftCurrencyFallbackWhenPurchasesUnavailable`: включить, если на площадке без покупок эту профессию можно купить за монеты.

### 3.5. Smoke test профессий

1. Запусти Play Mode с чистым save/profile.
2. Зайди в лобби.
3. Подойди к `ProfessionPoint`.
4. Открой UI профессий.
5. Проверь, что первая опция - `Без профессии`.
6. Нажми выбрать `Без профессии`.
7. Начни забег.
8. Проверь, что стартовых предметов/бонусов профессии нет.
9. Заверши забег и вернись в лобби.
10. Открой UI профессий.
11. Нажми random unlock.
12. Проверь, что списались монеты.
13. Проверь, что открылась случайная профессия.
14. Выбери открытую профессию.
15. Перезапусти Play Mode или перезагрузи проект.
16. Проверь, что выбранная профессия сохранилась.
17. Начни новый забег.
18. Проверь стартовые предметы и бонусы профессии.
19. Заверши забег.
20. Проверь, что профессия не сбросилась.

Direct buy fallback test:

1. Убедись, что текущая площадка без real payments.
2. Открой закрытую профессию.
3. Проверь, что direct buy показывает цену в монетах.
4. Нажми direct buy.
5. Проверь списание монет.
6. Проверь, что конкретная профессия открылась.

Direct buy real test:

1. Запусти на площадке, где `PurchasesManager.PurchasesAvailable()` возвращает true.
2. Укажи реальный `purchaseProductId`.
3. Открой закрытую профессию.
4. Нажми direct buy.
5. Проверь покупку.
6. После успешной покупки профессия должна открыться навсегда.

## 4. Карточки уровня

Эта система уже есть и должна оставаться run-only.

Как проверить:

1. Начни забег.
2. Получи опыт.
3. Открой выбор карточек.
4. Выбери карточку.
5. Проверь изменение статов в текущем забеге.
6. Заверши забег.
7. Начни новый забег.

Ожидаемый результат:

- карточка действует только в текущем забеге;
- после завершения забега бонус карточки сброшен;
- карточки не сохраняются как meta-progress.

Важно:

- яйца, животные, профессии и будущие классы нельзя хранить в `LevelStatManager.Stats`;
- это только временные статы забега.

## 5. Баланс и Google Sheets

### 5.1. Проверить credentials

Файл должен лежать тут:

- `UserSettings/Google/credentials.json`

Не должен лежать тут:

- `Assets/Resources/credentials.json`

### 5.2. Экспорт баланса

1. Открой:
   - `Tools -> Balance -> Google Sheets Sync`
2. Проверь путь к credentials.
3. Включи галочки:
   - Eggs;
   - Professions;
   - Boosters.
4. Нажми Export.
5. Открой Google Sheet.
6. Проверь, что появились колонки профессий:
   - `availableInRandomUnlockPool`;
   - `randomUnlockWeight`;
   - `directSoftCurrencyCost`;
   - `directSoftCurrencyType`;
   - `purchaseProductId`;
   - `allowSoftCurrencyFallbackWhenPurchasesUnavailable`.

### 5.3. Импорт баланса

1. В Google Sheet измени одно безопасное значение, например цену профессии.
2. В Unity нажми Import.
3. Открой `ProfessionCatalog.asset`.
4. Проверь, что значение изменилось.
5. Если это был тест, верни значение обратно.
6. Нажми Save Assets.

Важно:

- импорт яиц пока не покрывает полностью animal stages/hatch weights;
- для яиц полная таблица стадий и весов - отдельная следующая задача.

## 6. AI Game Developer / Unity-MCP

Проверить:

1. Открой `AI Game Developer`.
2. Убедись, что выбран AI agent `Codex`.
3. Убедись, что Model Context Protocol configured.
4. URL должен быть `http://localhost:22348`.
5. Для быстрой проверки из корня проекта запусти:
   - `npx unity-mcp-cli status E:\GitFork\dead_boat --timeout 15000 --verbose`;
   - `npx unity-mcp-cli run-tool editor-application-get-state E:\GitFork\dead_boat --input "{}" --timeout 30000 --raw`;
   - `npx unity-mcp-cli run-tool scene-list-opened E:\GitFork\dead_boat --input "{}" --timeout 30000 --raw`.

Ожидаемый результат:

- Unity-MCP отвечает;
- Codex видит Unity;
- Console читается;
- ошибок нет.

Если Unity-MCP не отвечает:

1. В `AI Game Developer` нажми Reconfigure для MCP.
2. Проверь `.codex/config.toml`, URL должен быть `http://localhost:22348`.
3. Если не помогло - перезапусти Unity.
4. Если не помогло - запусти `npx unity-mcp-cli status E:\GitFork\dead_boat --timeout 15000 --verbose` и смотри, какой URL/порт использует CLI.
