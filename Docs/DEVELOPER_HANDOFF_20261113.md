**Срез: 13 ноября 2026 года, время Москвы. Ветка: `codex/online-photon-fusion`. Репозиторий: `https://github.com/NikEvgesha/dead_boat`.**

В этот пакет собрана сохранённая работа нескольких чатов: новые и переработанные локации, зимний LevelEvent, двадцать находок, локальный босс на санях, единая деревня и исправления размещения предметов. Часть объектов существует только в мастерских. **`in_review` означает ожидание конкретной приёмки, а не отсутствие реализации.** Новый санный босс работает локально; его сетевая репликация не реализована. Новая WebGL-сборка этим пакетом не публикуется.

**Отправка подтверждена:** основной пакет сохранён в коммите [`34d808e9846e72e9fe0b1e7317c9c3e07ebc9071`](https://github.com/NikEvgesha/dead_boat/commit/34d808e9846e72e9fe0b1e7317c9c3e07ebc9071) и отправлен в `origin/codex/online-photon-fusion`. ## Как получить пакет и начать работу

Проект использует **Unity 6000.3.9f1**, точная ревизия записана в `ProjectSettings/ProjectVersion.txt`. Пакеты восстанавливаются по `Packages/manifest.json` и `packages-lock.json`; Photon Fusion SDK уже версионируется в `Assets/Photon`. Не заменять SDK и версии пакетов ради первого импорта без воспроизведённой ошибки.

Для новой рабочей копии:

```powershell
git clone --branch codex/online-photon-fusion https://github.com/NikEvgesha/dead_boat.git
cd dead_boat
git log -3 --oneline
```

Для существующего клона с сохранёнными собственными изменениями:

```powershell
git fetch origin
git switch codex/online-photon-fusion
git pull --ff-only
```

Не выполнять reset/clean поверх своей работы. При конфликте карточек сохранять сведения обеих сторон согласно `Docs/kanban/README.md`. Внешние настройки с секретами, кэши Unity и состояние текущей запущенной игры в этот пакет не входят. Для Mirra Cloud локальная конфигурация создаётся отдельно; `Assets/MirraCloud/` намеренно исключён из Git. Ключи в этот документ не помещены.

Сначала прочитать этот файл, затем `AGENTS.md`, `Docs/kanban/README.md` и карточку выбранной задачи. Старые `START_PROMPT.md`, `GPT_JOURNAL.md` и спецификации сохраняют историю: более поздняя карточка и фактический код могут уточнять раннее описание.

### Босс на санях

Редактируемый источник — `ArtSource/NewYearBoss/SleighThief.blend`, Unity-модель/материалы — `Assets/Events/NewYear/Models`, общий визуал — `SleighThief_Visual.prefab`, боевой префаб — `Boss244/SleighThief_Boss.prefab`. Runtime-код: `SleighBossController`, `SleighGiftAttack`, `SleighBossEncounter` в `Assets/Scripts/Enemy/`.

В обычном **одиночном** LevelEvent финал через штатный BossSpawner использует санного босса. Это опциональный `_soloBossOverride`; в сетевом SharedRunContext остаётся прежний сетевой босс. Другие карты сохраняют прежних боссов. Повторный сигнал финиша не создаёт дубликат; смерть финального санного босса связана со штатным Win.

Актуальное развитие после ранних прототипов:

- три цвета подарков, по пять снарядов в обычных атаках; сохранены предупреждения/взрывы и отмена опасных снарядов после смерти;
- злая мимика сохранена overrides общего визуального префаба; пересоздание из сырого FBX её потеряет;
- DB-ON-254 изменила прежнее снижение с сосульками на прямой горизонтальный пролёт: три последовательных вертикальных выпуска на 1/2/3 секунде, высота текущей конфигурации 7 м над опорой, без наведения падающих сосулек; урон 18;
- добавлена низкая круговая атака с вероятностью выбора 20%: до восьми подарков, радиус окружности 3,5 м; урон подарка 17, радиус взрыва 1,65 м;
- текущий смешок — три цельных фрагмента исполненной записи remarknl, Freesound 197411, CC0. Источник, лицензия и обработка сохранены в `ArtSource/NewYearBoss/Audio247/` и `audio247.json`. Генераторы 245/246 восстановят отвергнутый старый звук; их нельзя запускать как «последнюю сборку аудио».

Ранее в DB-ON-250 проверены финальный порог 50 000 м, один экземпляр босса, удар мечом, урон/уклонение, Win и снижение над реальной лодкой. **Последние** атаки DB-ON-254 проверены на ровной открытой поверхности: 11,92 м фактического пролёта, три попадания сосулек, восемь взрывов радиальной атаки, HP игрока 92 → 75. Эти результаты не подтверждают новые заходы над всеми крышами и узкой лодкой. Сетевая версия саней и WebGL-приёмка ещё нужны.

4. **Разработчик/ИИ:** проверить одиночные игровые сценарии в обычной генерации: добыча/продажа/топливо, входы и навигация охраны, ловушки/порталы, финал. Прогулка без боя и ускоренный старт перед боссом не заменяют обычный маршрут.
5. **Разработчик/ИИ:** выполнить отдельную сетевую интеграцию санного босса; проверить общую генерацию новых пулов/предметов, возвращение и смену ведущего, состояния ловушек. Сейчас онлайн сохраняет прежнего босса.
6. **Владелец и разработчик:** после этих проверок согласовать целевую WebGL-сборку, тест двумя клиентами и публикацию. Покупка тарифов и публикация не выполняются автоматически.
