# Прототип сетевых аватаров в лобби

Сцена `Assets/Scenes/Lobby.unity` содержит объект `Lobby Online`. При переходе в лобби Photon Fusion Shared подбирает свободную комнату или создаёт новую. Лимит задаётся полем `Lobby Capacity` на объекте сцены (по умолчанию 10). При подключении тот же `NetworkRunner` сначала читает список комнат custom lobby: если комната одна, занимает её до лимита; если несколько, выбирает комнату с наименьшим числом игроков. При пустом или задержавшемся списке используется Photon `FillRoom`; при гонке за последнее место подбор повторяется. Комнаты с другим лимитом отфильтровываются. Все публичные комнаты этого прототипа находятся в отдельном Photon lobby `river-public-lobby-v2`, поэтому тестовая комната старой версии не участвует в подборе. Каждый клиент создаёт сетевой аватар Kenney; собственная модель скрыта, так как игрок продолжает управлять существующим персонажем от первого лица. Положение и поворот передаются через `NetworkTransform`, а скорость движения включает анимацию ходьбы у других игроков. Активный предмет из инвентаря передаётся как компактный сетевой ID: у других игроков появляется его облегчённая модель в правой руке, а рука плавно принимает позу удержания. Для винтовки и дробовика поднимается также левая рука. Стартовый меч `saber` и покупаемые используемые предметы поддержаны; предметы в инвентаре, которые игрок не взял в руки, не отображаются.

При ошибке подключения или обрыве игра остаётся доступной в одиночном режиме. Пока здесь нет приглашений, чата, друзей и совместного забега. Глобальный предел игроков во всех комнатах требует отдельного сервиса учёта; текущий лимит действует на каждую комнату. Текущая тестовая конфигурация фиксирует регион `eu`, поэтому все тестовые клиенты встречаются в одном регионе.

Вход в лобби больше не удаляет незавершённое одиночное сохранение. Оно очищается при явном запуске новой одиночной игры через `LobbyManager.StartGame()`; обычный `GameManager.EndGame()` по-прежнему завершает текущий забег. После отказа Photon доступен `LobbyOnlineBootstrap.RetryConnection()`.

При первом входе в лобби игрок выбирает онлайн или офлайн; режим сохраняется локально. В следующих посещениях лобби используется сохранённый выбор. Панель режима открывается кнопкой в правом верхнем углу либо клавишей `O` при захваченном курсоре. В офлайне `NetworkRunner` не создаётся; при переключении из онлайна он закрывается. Ошибка подключения оставляет доступным одиночный режим и кнопку повторной попытки. Оба существующих маршрута выбора одиночной игры (`LevelMapUI` и `LobbyManager`) теперь закрывают Photon до загрузки уровня, не меняя сохранённого выбора режима.

Для проверочной WebGL-сборки передайте символ `DEADBOAT_ONLINE_DIAGNOSTICS` через `BuildPlayerOptions.extraScriptingDefines` или включите его только в WebGL Scripting Define Symbols на время сборки черновика. Он включает панель со стадией подключения, регионом, комнатой, числом игроков, краткой причиной отказа и кнопкой повторного подключения. В Unity Editor панель включена всегда. Подписи панели английские: стандартный IMGUI-шрифт в WebGL не отобразил кириллицу. Секреты, App ID и данные игрока на ней не выводятся. Обычная release-сборка без символа панель не содержит. При проверке черновика испытайте отключение сети и повторное подключение; до этого шаги `DB-ON-004` и `DB-ON-006` не считаются принятыми.

Подбор использует [официальное описание Photon Fusion Matchmaking](https://doc.photonengine.com/fusion/v2/manual/connection-and-matchmaking/matchmaking): Shared без `SessionName` ищет комнату или создаёт новую, `SerialMatching` распределяет игроков между доступными комнатами.

## Сборка

1. Установить Photon Fusion 2.1.3 в Unity. Папка `Assets/Photon/` исключена из Git.
2. В `Assets/Photon/Fusion/Resources/PhotonAppSettings.asset` указать **Fusion 2.1 App ID**; обычный Photon App ID `3e9e676b-8a22-47e0-9ed0-110f9032bf32` даёт ошибку `FusionPlugin21/Default` и не подходит. Для теста выставить `FixedRegion = eu`, `Protocol = WebSocketSecure`, `Port = 443`. Этот файл не хранится в Git.
3. Выполнить в Unity `Tools > Fusion > Rebuild Prefab Table`, чтобы `LobbyNetworkAvatar` попал в таблицу сетевых префабов. После повторной установки SDK это обязательный шаг.
4. Собрать обычный WebGL-плеер со сценами из Build Settings. Для быстрой проверки только лобби можно временно собрать `Assets/Scenes/Lobby.unity` как единственную сцену; сам список Build Settings менять не требуется.

`LobbySceneManager` обслуживает только готовую сцену лобби без сетевых объектов сцены. При добавлении совместного забега потребуется отдельный менеджер загрузки сетевых сцен.

Модель `character-a` взята из Kenney Blocky Characters; условия использования находятся в `Avatars/Kenney/License.txt`.

## Mirra Cloud: отдельная проверка WebGL

Пакет `com.mirrahub.cloud-sdk` закреплён на версии `v0.10.0`. Он отличается от установленного `MirraSDK 5` для площадок и рекламы. Для теста создан отдельный проект Mirra Cloud `Dead Boat`, ветка `main`, платформа `yandex-games` типа Web с гостевым входом. Гостевой аккаунт нужен только для первой проверки соединения: он привязан к локальным данным браузера и не решает задачу постоянной личности между устройствами.

В `Assets/Online/SmokeTest/MirraCloudConnectionSmokeTest.unity` проверяется только гостевой вход. Сцена не включена в обычный маршрут игры. После настройки локального `Assets/MirraCloud/Resources/Configuration.asset` собрать её через `Tools > Dead Boat > Build Mirra Cloud Smoke Test` или `-executeMethod DeadBoat.Online.SmokeTest.Editor.MirraCloudSmokeBuild.Build`. Результат помещается в игнорируемую Git папку `Builds/MirraCloudSmokeTest`. В конфигурации нужны Project ID, `BranchId = main`, `PlatformKey = yandex-games`; поле `Token` должно быть пустым. По коду SDK v0.10.0 оно используется инструментами Editor, но не гостевым входом. Сборщик прерывает WebGL-сборку при заполненном поле, чтобы не вложить API-токен в публичный архив. Конфигурация и её `.meta` исключены из Git; серверные ключи и секрет Яндекс Игр в Unity не добавлять. Сборщик добавляет локальные JS-зависимости WebView, которые SDK v0.10.0 требует даже для гостевого входа.

Для запроса CSP в Яндекс Играх можно собрать **полноценный игровой черновик** через `Tools > Dead Boat > Build Mirra Cloud Playable Draft` или `-executeMethod DeadBoat.Online.SmokeTest.Editor.MirraCloudSmokeBuild.BuildPlayableDraft`. Используются все включённые сцены Build Settings; результат — `Builds/MirraCloudPlayableDraft`. Символ `DEADBOAT_MIRRA_DIAGNOSTICS` действует только в этой сборке: поверх игры появляется маленькая панель гостевого входа и повторной попытки, а не новая стартовая сцена. Ошибка Mirra не блокирует обычную игру. Сборщик также требует пустой `Configuration.Token` и добавляет JS-зависимости WebView. Для обычного релизного билда этот метод не применять.

Проверка в черновике Яндекс Игр должна показать `Guest login OK`; при ошибке сцена показывает HTTP-код и краткую причину. Для постоянных друзей потребуется отдельно настроить подтверждённый вход Яндекс Игр: интеграция Mirra Cloud запрашивает ID приложения и секретный ключ, который хранится только на стороне Mirra Cloud. После проверки тестовая сцена не заменяет основной билд игры.

## Предметы в руке

Каталог `Assets/Online/Avatars/HeldItems/LobbyHeldItems.asset` связывает сетевые ID с визуальными префабами. При добавлении нового используемого предмета в `Assets/Prefabs/Items` запустите `Tools > Online > Rebuild Held Item Visuals`. Скрипт создаёт только модель с материалами, без скриптов и физики, и сохраняет уже настроенные ID, масштаб и положение. Если предмет остаётся без записи в каталоге, другие игроки увидят пустую руку; настройте его позу в каталоге.
